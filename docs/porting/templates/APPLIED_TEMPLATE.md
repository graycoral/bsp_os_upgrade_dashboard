# 회사 이식 이력

빈 양식이다. 회사 저장소의 `docs/porting/APPLIED.md`로 복사해 작성한다. 회사 전용 내용은 공개 원본에 올리지 않는다. 코드 적용 상태와 시험 결과를 분리하고 이전 실패·부분 적용 기록을 보존한다.

## 기능별 현황

| PORT ID·안내서 기준 | 원본 기준→대상 커밋 | 회사 적용 커밋 | 적용 상태 | 회사 시험·실행 기록 | 남은 범위 |
|---|---|---|---|---|---|

적용 상태: UNKNOWN / PARTIAL / BLOCKED / APPLIED. 시험 상태: PASS / FAIL / BLOCKED / NOT_RUN. APPLIED는 지정 코드 범위의 반영 상태이며 실제 환경 인수 완료를 뜻하지 않는다. 일부 기능만 가져온 경우 마지막 원본 커밋 하나로 전체 적용을 표시하지 않는다.

## 실행별 기록 — 아래 항목을 매 실행 추가

- 일시 / 담당 / PORT ID / 사용한 안내서 revision:
- 원본 기준·대상 커밋 / 회사 작업 전·후 커밋:
- 증거로 확인된 해당 기능의 완전 반영 원본 기준 / 근거 (없으면 UNKNOWN):
- 최근 조사 또는 부분 적용 목표 / 미반영·보류·실패 항목 (완전 반영 기준과 별도):
- 미커밋이면 변경 파일·내용 해시 / 커밋 후 연결 기록:
- 선행 기능 확인 / 이미 반영된 부분:
- 실제 적용 파일·동작 / 회사 방식으로 조정한 부분·이유:
- 부분 적용·보류·제외 범위와 근거:
- 시험 ID·실행 명령·환경·코드 기준·PASS/FAIL/BLOCKED/NOT_RUN·증거:
- 독립 리뷰 상태 / 실제 검토 근거:
- 실제 회사·장비 인수 결과 또는 NOT_RUN:
- 다음 조치·담당 / 구조 대응 기록 변경:

| 변경 항목 | 회사 대응 파일·접점 | 항목별 처리 | 판단 근거·지정 시험 및 결과 |
|---|---|---|---|
| | | | |

항목별 처리는 적용 / 기존 동등 / 회사 맞춤 / 보류 / 해당 없음과 이유를 기록한다. 이는 위 기능 전체의 적용 상태와 별개다. 최초 조사에서는 확인한 코드·동작·시험과 비교 기준을 근거로 남기고 불명확하면 UNKNOWN으로 둔다. 이력이 없으면 선택 기능 접점만 조사하며 기준을 추정해 APPLIED로 표시하지 않는다.

조사 시 제안 처리와 실제 처리를 구분한다. 조사만으로 완전 반영 기준을 전진하거나 기능 적용 상태를 변경하지 않는다. 회사 코드의 동등 확인만으로 실제 회사 인수 PASS를 표시하지 않는다.

현황 표는 최신 실행을 가리키게 갱신하고, 실행별 기록은 추가 방식으로 남긴다. 원본 검증을 회사 시험 결과로 옮겨 적지 않는다.
