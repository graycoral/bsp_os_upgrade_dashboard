BSP OS 업그레이드 시스템 구성

실행의 기준은 서버에 저장된 상태입니다. BSP 업그레이드와 GUI Test는 각각의 실행 규칙과 저장소를 유지하며, 화면은 확정된 기록을 조회합니다.

블루프린트 · 사용자 지정기본 · 밝은 미니멀 보기GUI Test 상세근거·범위

01. 전체 구성

게이트를 통과한 작업만 실행

모든 모듈의 분석은 병렬로 진행할 수 있습니다. 설계 이후에는 최초 계획 확인이 필요하며, 나머지 모듈은 부트로더 선행 그룹 전체 완료를 기다립니다. 수정과 빌드는 같은 배타 자원을 사용합니다. API와 worker는 분리되고, GUI worker는 통합 worker 프로세스 안에서 별도 풀로 실행됩니다.

자동 Claude 조정은 설계 단계

현재 v1 실행 경로와 별도 수동 Claude 패키지를 제공합니다. 자동 조정 O1~O5·모듈 보고 v2는 미구현입니다. 계획 제안과 실제 프로세스 배정·결과 확정의 권한은 구분합니다.

02. GUI Test와 Windows 실행기

실행 위치와 논리 상태를 분리

Manager가 Preflight·예약·반복 계획·최종 판정을 관리합니다. 원격 모드에서는 Windows 실행기가 소스 snapshot과 검증된 Python 명령으로 TC를 실행합니다. 어댑터는 ID·요청 해시·소스 기준을 확인하며 로그와 종료 결과를 수집합니다. Mock 이력은 별도 DB에 보존됩니다.

실제 장비 검증은 별도

실제 Linux·SSH·공유 폴더·COM/보드 인수는 완료되지 않았습니다. 보드 이미지·매핑 근거가 없는 실제 Job 자동 결과 반영은 비활성입니다. 초기 BSP 장비 시험은 사례별 수동 PASS/FAIL과 별도 최종 검토를 유지합니다.

근거와 표현 범위
  • 현재 커밋: 5d2f680a368e5873632b087baccb057be8b621be. 이전 구성도의 코드 근거를 재사용하고 관련 backend·Core·runner 파일의 변경이 없음을 확인했습니다.
  • 기준 문서: 시스템 구조, GUI Test 계약, 오케스트레이터 명세.
  • 코드: backend/api/main.py, backend/worker/main.py, backend/domain/engine.py·policy.py, backend/adapters/bridge.py, gui_test/runtime.py, gui_test/core/manager.py·worker.py, gui_test/adapters/windows_remote.py, gui_test/execution/host.py.
  • 전체 그림에서는 각 도구·빌드를 한 노드로 묶었습니다. GUI 원격 어댑터·실행기·소스·TC·단독 앱은 상세 그림에 유지했습니다. 두 그림 사이의 동일 구성은 확대 설명을 위한 중복 표현입니다.
  • API의 산출물 다운로드와 worker의 Jira 직접/MCP 판단 연결은 보조 경로로 설명만 남겼습니다. Jira 실제 사내 인수는 미완료이며, 일반 오류를 무조건 Jira로 보내지 않습니다.
  • 1280 × 720 문서용 구성도 2장. 정적 HTML·인라인 SVG이며 모바일은 그림 내부에서 가로 스크롤합니다. 웹 글꼴을 가져올 수 없으면 로컬 글꼴로 대체됩니다.
