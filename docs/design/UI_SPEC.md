# 화면 명세 — 모듈 비교형

기존 3번 시안의 배치를 기준으로 하며 기능 상태는 최신 요구사항을 따른다. 초기 화면에 자동 보드팜을 필수 실행 경로처럼 표시하지 않는다.

## 상단과 종합 진행도

- 작업 이름·OS 기준·Linux 환경·작업 폴더·현재 계획 버전·전체 상태·마지막 갱신 시각 표시.
- Start, 재개, 신규 배정 일시 중지, 설정 제공. Start 중복 클릭은 동일 명령으로 처리하고 접수 상태를 표시한다.
- 제목 **종합 진행도** 아래 분석 / 구현 / 검증 / 빌드 / 테스트를 하나의 컴팩트 진행 띠로 표시한다. 각 구획에 단계 이름·진행률·완료/필수 수를 함께 보여주고 해당 없음과 0%를 구분한다. 독립된 대형 카드나 화살표를 사용하지 않는다. 실패·대기·재검증 설명과 모듈별 상태는 아래 표에서 유지한다.
- 전체 진행률, 선행 그룹/나머지 그룹, 통합 검증, 최종 검토는 별도로 보여준다. “산정 중”, “해당 없음”, “연결 끊김·마지막 확인 시각”을 0%와 구분한다.

## 2026-11-04 메인 종합 화면 정리 · D-52

RQ-19/20의 P3 표시 개선이다. 데스크톱(1101px 이상)에서는 다섯 단계를 높이 160px 이내의 한 줄로 배치하고, 1100px 이하에서는 각 단계를 이름/진행률과 막대/완료 수의 컴팩트 두 줄 행으로 표시한다. 진행 수치·막대는 기존 파란 강조색 하나를 사용한다. 성공·실패·실행·대기 등 의미가 있는 배지의 색상 구분은 유지한다.

주요 설명·단계 이름·집계·표 상태/대기 이유는 12~13px와 텍스트 대비 4.5:1 이상을 기준으로 한다. 진행률에는 고정폭 숫자를 적용하며 키보드 포커스는 즉시 표시한다. 모션 줄이기 설정에서는 종합 화면의 진행 막대 전환을 생략한다.

600px 이하에서는 제목/동작을 세로 배치하고 필터는 버튼 단위로 줄바꿈한다. 검색·작업 선택은 사용 가능한 전체 너비를 쓰며 긴 작업 이름·소스 기준·작업 경로는 줄바꿈한다. 320/375/414/768/1280px에서 페이지 가로 넘침이 없어야 하며 모듈 표 자체의 가로 스크롤은 유지한다.

공통 셸에서 기능 없는 `ENGINEERING WORKSPACE`, `WORKSPACE`, `UPGRADE CONTROL ROOM`, 상단의 고정 장비 테스트 문구와 `U` 아바타를 제거한다. 메인 종합 화면의 추가 스타일은 활성 `app--overview` 안의 해당 컴포넌트로 제한하여 숨겨진 다이어그램과 GUI Test 화면에 전파하지 않는다. 서버 집계·N/A·최초 계획/선행 그룹 게이트·통합 검증/최종 검토·조회 수용 규칙·기존 동작은 유지한다. 검증 범위는 화면 fixture와 기존 회귀이며 실제 외부 연결이나 장비 실행을 포함하지 않는다.

## 모듈 표

열: 펼치기 / 모듈·그룹 / 분석 / 설계 / 코드 / 빌드 / 검증 / 장비 테스트 / 현재 작업·상태 / 담당 / 진행률.

접힌 행에서도 `카메라 · 분석 완료 · 선행 그룹 장비 시험 대기`처럼 무엇을 했고 왜 기다리는지 표시한다. 상태는 색 외에 아이콘·문자로 구분한다. 행 클릭과 키보드 Enter/Space로 펼칠 수 있으며 펼침 상태를 접근성 속성으로 제공한다.

펼친 영역: 현재 기준·변경 목록, 단계별 필수 작업, 실패 사유, 재시도 버튼, 입력/산출물·로그, 에이전트/리뷰 담당과 세션, attempt 이력, 관련 판단/Jira, 수동 시험 등록. 과거 실패·무효화된 PASS는 회색 처리하되 숨기지 않는다.

재시도 버튼은 FAILED 등 허용 상태에만 표시/활성화하고 불가 사유를 설명한다. `UNKNOWN: 이전 실행 상태 확인 필요`이면 중복 재실행을 막는다. 수동 시험 재시도는 “새 수동 시험 기록”이라는 의미를 분명히 한다.

## 보조 패널

- 프롬프트: 대상 모듈/작업, 자연어 명령, 해석된 의도·범위, 접수/실행/결과 이력. 새 판단이나 범위 변경이 있을 때만 구체적 확인을 요청한다.
- 검토/Jira: 내부 검토 ID, 질문, 의존 작업, 동기화 상태, 외부 링크, 결정 완료와 구현 반영 상태. 연결 실패 때문에 목록이 사라지지 않는다.
- 수동 시험: 이미지 묶음·해시·방법 다운로드, case별 PASS/FAIL만 필수. 「추가 정보 (선택)」에 보드·수행자·시각·해시·근거 업로드를 접어서 제공한다. 미입력은 허용하고 입력된 잘못된 값은 오류로 표시한다.
- 설정: Linux 계정/경로와 사전 점검, 도구별 설치/인증/기능, Jira 직접/MCP 선택. MCP는 실제 Claude 환경 범위를 표시한다.

## 화면 상태와 사용성

빈 작업/로딩/권한 없음/부분 실패/연결 끊김/재연결/오래된 기준/취소 중을 별도로 설계한다. 변경 요청 중에는 접수 ID를 유지하고 화면 새로고침으로 새 명령을 만들지 않는다. 선택한 모듈·필터·펼침 상태를 갱신 시 유지한다. 서버 버전이 뒤인 응답은 무시하고 누락 발생 시 snapshot을 다시 읽는다.

작은 화면에서는 표의 가로 스크롤과 고정 모듈 열을 사용한다. 상태 설명·근거·기본 동작을 색이나 마우스 hover만으로 전달하지 않는다. 로그와 MCP 응답의 HTML/스크립트는 실행하지 않고 텍스트로 표시한다.

## 데모 선행 수동 완료

데모 작업의 미완료 선행 모듈을 펼치면 「데모에서 이 모듈 완료」를 제공한다. 최초 계획·일시 중지·사람 판단 상태에 따라 비활성화 사유를 표시한다. 완료 이력에는 실제 실행/시험이 아닌 데모 수동 완료임을 명시한다. 실제 모드와 나머지 그룹에는 제공하지 않는다.

## 첫 화면 (D-38)

로컬 또는 SSH 터널 주소를 열면 접속 키 입력 없이 바로 대시보드가 나타난다. 연결 실패는 상태 표시로 안내하고 로그인 화면으로 전환하지 않는다. 새 업그레이드를 누르기 전에는 실행을 자동 생성하지 않는다.

## 오케스트레이터 표시 — 추가 설계, 미구현

- 상단/보조 영역에 「작업 조정」 상태와 마지막 검토 시각·대상 계획을 표시한다. 대기/검토 중/결과 있음/연결 실패/상태 확인 필요/한도 도달을 모듈 실행 상태와 구분한다.
- 제안 목록은 대상·이유·근거·다음 행동과 서버의 적용 결과를 보여준다. 「제안됨」「사용자 선택 대기」「명령 접수」「실행 완료」를 같은 완료 표시로 합치지 않는다. 오래된 제안은 「이전 기준 · 재검토 필요」로 표시하고 적용을 막는다.
- 모듈 상세에는 원본 보고와 별도의 조정 의견을 보여준다. 조정자의 해석으로 모듈의 실제 오류·리뷰·과거 실패를 덮어쓰지 않는다. v1 자료의 미제공 항목은 「보고되지 않음」으로 표시한다.
- 기존 실패 재시도 버튼을 유지한다. 자동 재시도 허용 전에는 제안의 수정 방향을 확인하고 사용자가 실행을 선택한다. 최초 계획/새 판단/최종 검토 외에 정상 단계마다 추가 승인을 요구하지 않는다.
- 판단 후보는 Jira 발행 여부와 분리하여 즉시 표시하고 영향 범위 보류 이유를 연결한다. 후보 접수/내부 판단 생성/Jira 연결/사람 결정/반영 완료를 구분한다. 조정 장애 시에도 사람이 후보를 검토할 수 있다.
- 설정에는 조정 활성화·호출 시간/횟수·재계획 한도·자동 재시도 한도와 wrapper 지원 상태를 표시하는 안을 추가한다. 새 값은 새 작업부터 적용하며 현재 UI에는 아직 없다.
- 진행도는 계속 서버 집계다. 조정 성공 횟수나 AI가 말한 퍼센트를 종합 진행도에 더하지 않는다. 일반 화면 새로고침으로 오케스트레이터를 호출하지 않는다.

표시 상태/권한 판단의 원천은 [오케스트레이터 명세](ORCHESTRATOR_SPEC.md)다. UI T-84와 실제 연동 T-85가 PASS가 되기 전 이 화면이 구현됐다고 안내하지 않는다.

## 수동 Claude 패키지의 현재 범위

이번 수동 Claude 패키지에서는 UI를 변경하지 않는다. 제안 JSON과 CLI의 WAITING_USER/BLOCKED/STALE은 검토 자료이며 대시보드에 반영된 상태가 아니다. 기존 화면의 사용자 명령을 통한 실행만 유지한다. [사용 안내](../agents/CLAUDE_ORCHESTRATOR_GUIDE.md)를 따른다.

환경 설정의 「고정 소스 커밋/해시」를 「소스 기준 (선택)」으로 변경했다. 자동 Git 기록과 데모 기준을 안내하며 예전 demo-os-v1 값은 자동 기록 버튼으로 비울 수 있다. 브리지 기본 경로·빈 항목 채우기·사용자 지정 값 보존·파일별 점검 표시를 제공한다. 기본 경로 그대로인 필드는 작업 폴더를 바꿀 때 같이 갱신한다. [설정 사용법](../agents/ENVIRONMENT_AND_BRIDGES.md)을 따른다.


## D-42 환경 설정 화면

에이전트·빌드 연결의 기본 선택은 내장 CLI 자동 탐지다. 작업/소스 폴더, 선택 지침 폴더, 빌드·검증·최종 통합 명령과 산출물 위치를 표시한다. CLI 경로/모델/선택 도구 해제/역할 파일 매핑은 접이식 고급 설정으로 둔다. JSON 실행 배열과 경로 채우기는 기존 브리지 모드에서만 보인다. 자동 탐지가 설치/로그인/실제 실행을 모두 의미하는 것으로 표시하지 않는다.

저장·JSON 가져오기/내보내기·재접속을 지원하고 기존 작업에는 소급하지 않는다. 조정 연결 실패는 실패 근거와 로그인 확인 후 연결 재시도 버튼을 표시한다. 실행 불명은 자동 재시도 버튼으로 풀지 않는다. 상세 설정 의미는 [환경 안내](../agents/ENVIRONMENT_AND_BRIDGES.md)를 따른다.

## GUI Test 작업 화면 · 현재 기준

RQ-39~43 / D-44~46. Windows 단독과 Dashboard는 같은 React 화면을 사용한다. 중간 시안과 과거 검증은 testing/runs에 보존하며 아래가 현재 동작이다.

| 영역 | 동작 |
|---|---|
| TC 검색 패널 | 아이콘 숨김/복원, 우측 경계 240~600px 조절 및 좌우/Home/End 키. 실제 너비는 화면 폭에 제한된다. 700px 이하에서는 1열이며 조절 핸들을 숨긴다. |
| TC 트리 | 이름/경로 검색, 연결 유형 필터, 폴더별 선택/부분 선택/접기. 폴더 선택은 보이는 하위 TC에만 적용하고 필터 밖 선택을 유지한다. |
| 목록 열 | 이름·유형·시간 제목 클릭으로 정렬 방향 전환/화살표 표시. ↶는 실행 순서 보기. 정렬은 실행 요청 순서를 바꾸지 않는다. |
| TC 행 | 기본 높이32px/이름12px, 이름·유형·제한 시간·반복 아이콘 한 줄. 실행 순서는 TC 드래그로 변경하며 위아래 이동 버튼은 제공하지 않는다. 긴 이름/경로·제한 정보는 툴팁으로 확인한다. |
| 실행 순서 | 선택한 TC 행을 대상 행 앞/뒤로 드래그하여 이동. 번호 없음. 전체 실행 순서 펼침 목록에서 폴더 경계를 넘는 순서를 확인한다. 변경 시 Suite 기준/Preflight 해제, 기존 Run 순서는 불변이다. |
| 반복 횟수 | 아이콘 클릭 시 TC 횟수 입력. 기본1은 숫자를 생략하고 변경 시 ×N. 전체 반복은 실행 설정에 두며 결과 상단에 예정 총량을 표시한다. |
| 설정 탭 | 소스/Git·Suite·연결·실행을 톱니바퀴 탭에 모으고 개별/전체 접기를 제공한다. 숨김 처리로 입력을 보존하며 제목 버튼 Enter/Space를 지원한다. |
| 결과 복귀 | 결과 탭, 명시적 돌아가기, 톱니바퀴 재클릭, 설정 내부 Esc. 결과 탭으로 포커스를 복원한다. 탭 방향키/Home/End를 지원한다. |
| 결과와 실행 | 결과 탭이 기본 화면이다. 결과 카드가 위, 별도 접이식 실행 카드가 아래다. 실행 카드에 Preflight/시작/일시정지·재개·중단·제어권·재검증을 모은다. Run 선택은 설정 아이콘 왼쪽에 두고 결과·설정 화면에서 공통 표시한다. 결과 요약/제어 중·관찰 모드/진행률/완료 수·비용은 항상 보이며 세션 정보·결과 상세·로그는 각각 접고 펼친다. 설정 전환/접힘은 실행을 멈추지 않는다. |
| 재실행 | 별도 열 없이 FAIL 옆 작은 Retry. 원본 종료 전·관찰 모드·통신 끊김·처리 중 비활성. 새 Run으로 해당 TC1회, 원본 실패/비용은 보존한다. |
| 모델 사용량 | progress 아래와 TC 결과에 11px 모델별 입력/출력 토큰과 USD 비용. 모델 호출 없음/집계 없음/일부 집계를 구분한다. |
| 실행 대상 | 결과 상단과 TC 행에 local 또는 실제 보고된 A/B 보드 이름. 현재 설정값을 과거 결과에 대입하지 않는다. Mock 및 미기록을 표시한다. |

패널 접힘/숨김/너비만 localStorage에 저장한다. 저장소 접근 차단 시 현재 화면 조작은 유지한다. 상세 요청·반복 판정·어댑터 필드는 [GUI Test 계약](GUI_TEST_CONTRACT.md)을 따른다. 과거 UI 검증은 [10월 기록](../testing/runs/20261026-gui-ux.md), 현재 결과는 [게시 검증](../testing/runs/20261102-publication.md)에 연결한다.

2026-11-03 통합: TC 실행 명령 설정도 같은 설정 탭에 배치하고 전체 접기/펼치기에 포함한다. 미저장·유실 프로파일은 Preflight/시작/재검증/Retry를 차단한다. 명령 미리보기·프로파일 선택은 반복 설정과 함께 유지하고, 실제 실행 버튼은 결과 탭 아래의 별도 실행 카드에서 제공한다. RQ-45 / T-122~124.

## Test 현황 실제 연결 보기 · RQ-49

상단 ‘실제 연결 모드로 전환’으로 실제 작업공간을 연다. 미설정/미연결/실행기 연결됨을 표시하고 ‘연결 다시 확인’으로 재조회한다. 선택은 브라우저 저장소와 URL guiExecution=live/default를 따른다. 화면 재로드는 진행 중 Run을 중단하지 않는다. 가짜 TC/보드를 채우지 않고 Mock 마지막 Run/명령 선택을 분리한다. 준비 전 새 실행 버튼은 비활성이다.

## 다이어그램 탭 · RQ-50

새 탭에 `FrontEnd(ACON) → BackEnd(bsp-os-upgrade) → 선행 IP 모듈 그룹 → 일반 IP 모듈 그룹`을 가로 배치한다. 그룹의 각 IP 아래에서 단계 순서도를 접고 펼치며, 접힌 상태에서도 현재 단계·진행률·상태 점을 표시한다. Archify 스타일의 진행 선 효과와 연결/중단/시작 전 상태를 제공한다. 세부 레이아웃·상태/색상·모션·접근성·서버 단계 대응은 [전용 설계](WORKFLOW_DIAGRAM.md)를 단일 기준으로 한다.

문서 리뷰 후 사용자가 구현을 승인했다. ACON 실연결 근거는 미확정이며 API 연결 표시와 구분한다. 기존 실행 정책은 유지한다. 실제 구현·시험 결과는 [실행 기록](../testing/runs/20261103-workflow-diagram-implementation.md)을 따른다.

후속 리뷰의 표시 설계안: IP의 연결 점과 실행 배지를 분리하여 연결됨+대기/연결 단절+실행 지속을 함께 표현한다. 상위 그룹 연결은 설계 이후 게이트를 나타내고 병렬 분석은 일반 그룹 내부에서 표현한다. 현재 단계·유효성·취소 중·자동 Test와 조회 신선도, 펼침 유지/초기화·모션 정지·효율 기준은 전용 설계 3~5절을 따른다. 같은 이름의 기존 종합 진행도 집계는 변경하지 않는다.

2026-11-04: RQ-39 TC 트리의 전체 펼치기·접기 제어는 각각 + / − 아이콘 버튼으로 표시한다. 기존 동작을 유지하고 한국어 접근 가능한 이름과 도구 설명을 제공하며 버튼 영역은 최소 24px이다.
