# 화면 명세 — 모듈 비교형

기존 3번 시안의 배치를 기준으로 하며 기능 상태는 최신 요구사항을 따른다. 초기 화면에 자동 보드팜을 필수 실행 경로처럼 표시하지 않는다.

## 상단과 종합 진행도

- 작업 이름·OS 기준·Linux 환경·작업 폴더·현재 계획 버전·전체 상태·마지막 갱신 시각 표시.
- Start, 재개, 신규 배정 일시 중지, 설정 제공. Start 중복 클릭은 동일 명령으로 처리하고 접수 상태를 표시한다.
- 제목 **종합 진행도** 아래 분석 / 구현 / 검증 / 빌드 / 테스트 카드. 큰 %와 완료/필수 수, 실패·대기·재검증 수를 표시한다. 화살표 사용 안 함.
- 전체 진행률, 선행 그룹/나머지 그룹, 통합 검증, 최종 검토는 별도로 보여준다. “산정 중”, “해당 없음”, “연결 끊김·마지막 확인 시각”을 0%와 구분한다.

## 모듈 표

열: 펼치기 / 모듈·그룹 / 분석 / 설계 / 코드 / 빌드 / 검증 / 장비 테스트 / 현재 작업·상태 / 담당 / 진행률.

접힌 행에서도 `카메라 · 분석 완료 · 선행 그룹 장비 시험 대기`처럼 무엇을 했고 왜 기다리는지 표시한다. 상태는 색 외에 아이콘·문자로 구분한다. 행 클릭과 키보드 Enter/Space로 펼칠 수 있으며 펼침 상태를 접근성 속성으로 제공한다.

펼친 영역: 현재 기준·변경 목록, 단계별 필수 작업, 실패 사유, 재시도 버튼, 입력/산출물·로그, 에이전트/리뷰 담당과 세션, attempt 이력, 관련 판단/Jira, 수동 시험 등록. 과거 실패·무효화된 PASS는 회색 처리하되 숨기지 않는다.

재시도 버튼은 FAILED 등 허용 상태에만 표시/활성화하고 불가 사유를 설명한다. `UNKNOWN: 이전 실행 상태 확인 필요`이면 중복 재실행을 막는다. 수동 시험 재시도는 “새 수동 시험 기록”이라는 의미를 분명히 한다.

## 보조 패널

- 프롬프트: 대상 모듈/작업, 자연어 명령, 해석된 의도·범위, 접수/실행/결과 이력. 새 판단이나 범위 변경이 있을 때만 구체적 확인을 요청한다.
- 검토/Jira: 내부 검토 ID, 질문, 의존 작업, 동기화 상태, 외부 링크, 결정 완료와 구현 반영 상태. 연결 실패 때문에 목록이 사라지지 않는다.
- 수동 시험: 이미지 묶음·해시·방법 다운로드, case별 PASS/FAIL만 필수. 「추가 정보 (선택)」에 보드·수행자·시각·해시·근거 업로드를 접어서 제공한다. 미입력은 허용하고 입력된 잘못된 값은 오류로 표시한다.
- 설정: Linux 계정/경로와 사전 점검, 도구별 설치/인증/기능, Jira 직접/MCP 선택. MCP는 실제 Claude 환경 범위를 표시한다.

## 화면 상태와 사용성

빈 작업/로딩/권한 없음/부분 실패/연결 끊김/재연결/오래된 기준/취소 중을 별도로 설계한다. 변경 요청 중에는 접수 ID를 유지하고 화면 새로고침으로 새 명령을 만들지 않는다. 선택한 모듈·필터·펼침 상태를 갱신 시 유지한다. 서버 버전이 뒤인 응답은 무시하고 누락 발생 시 snapshot을 다시 읽는다.

작은 화면에서는 표의 가로 스크롤과 고정 모듈 열을 사용한다. 상태 설명·근거·기본 동작을 색이나 마우스 hover만으로 전달하지 않는다. 로그와 MCP 응답의 HTML/스크립트는 실행하지 않고 텍스트로 표시한다.

## 데모 선행 수동 완료

데모 작업의 미완료 선행 모듈을 펼치면 「데모에서 이 모듈 완료」를 제공한다. 최초 계획·일시 중지·사람 판단 상태에 따라 비활성화 사유를 표시한다. 완료 이력에는 실제 실행/시험이 아닌 데모 수동 완료임을 명시한다. 실제 모드와 나머지 그룹에는 제공하지 않는다.
