# 화면 명세 — 모듈 비교형

기존 3번 시안의 배치를 기준으로 하며 기능 상태는 최신 요구사항을 따른다. 초기 화면에 자동 보드팜을 필수 실행 경로처럼 표시하지 않는다.

## 상단과 종합 진행도

- 작업 이름·OS 기준·Linux 환경·작업 폴더·현재 계획 버전·전체 상태·마지막 갱신 시각 표시.
- Start, 재개, 신규 배정 일시 중지, 설정 제공. Start 중복 클릭은 동일 명령으로 처리하고 접수 상태를 표시한다.
- 제목 **종합 진행도** 아래 분석 / 구현 / 검증 / 빌드 / 테스트 카드. 큰 %와 완료/필수 수, 실패·대기·재검증 수를 표시한다. 화살표 사용 안 함.
- 전체 진행률, 선행 그룹/나머지 그룹, 통합 검증, 최종 검토는 별도로 보여준다. “산정 중”, “해당 없음”, “연결 끊김·마지막 확인 시각”을 0%와 구분한다.

## 모듈 표

열: 펼치기 / 모듈·그룹 / 분석 / 설계 / 코드 / 빌드 / 검증 / 장비 테스트 / 현재 작업·상태 / 담당 / 진행률.

접힌 행에서도 `카메라 · 분석 완료 · 선행 그룹 장비 시험 대기`처럼 무엇을 했고 왜 기다리는지 표시한다. 상태는 색 외에 아이콘·문자로 구분한다. 행 클릭과 키보드 Enter/Space로 펼칠 수 있으며 펼침 상태를 접근성 속성으로 제공한다.

펼친 영역: 현재 기준·변경 목록, 단계별 필수 작업, 실패 사유, 재시도 버튼, 입력/산출물·로그, 에이전트/리뷰 담당과 세션, attempt 이력, 관련 판단/Jira, 수동 시험 등록. 과거 실패·무효화된 PASS는 회색 처리하되 숨기지 않는다.

재시도 버튼은 FAILED 등 허용 상태에만 표시/활성화하고 불가 사유를 설명한다. `UNKNOWN: 이전 실행 상태 확인 필요`이면 중복 재실행을 막는다. 수동 시험 재시도는 “새 수동 시험 기록”이라는 의미를 분명히 한다.

## 보조 패널

- 프롬프트: 대상 모듈/작업, 자연어 명령, 해석된 의도·범위, 접수/실행/결과 이력. 새 판단이나 범위 변경이 있을 때만 구체적 확인을 요청한다.
- 검토/Jira: 내부 검토 ID, 질문, 의존 작업, 동기화 상태, 외부 링크, 결정 완료와 구현 반영 상태. 연결 실패 때문에 목록이 사라지지 않는다.
- 수동 시험: 이미지 묶음·해시·방법 다운로드, case별 PASS/FAIL만 필수. 「추가 정보 (선택)」에 보드·수행자·시각·해시·근거 업로드를 접어서 제공한다. 미입력은 허용하고 입력된 잘못된 값은 오류로 표시한다.
- 설정: Linux 계정/경로와 사전 점검, 도구별 설치/인증/기능, Jira 직접/MCP 선택. MCP는 실제 Claude 환경 범위를 표시한다.

## 화면 상태와 사용성

빈 작업/로딩/권한 없음/부분 실패/연결 끊김/재연결/오래된 기준/취소 중을 별도로 설계한다. 변경 요청 중에는 접수 ID를 유지하고 화면 새로고침으로 새 명령을 만들지 않는다. 선택한 모듈·필터·펼침 상태를 갱신 시 유지한다. 서버 버전이 뒤인 응답은 무시하고 누락 발생 시 snapshot을 다시 읽는다.

작은 화면에서는 표의 가로 스크롤과 고정 모듈 열을 사용한다. 상태 설명·근거·기본 동작을 색이나 마우스 hover만으로 전달하지 않는다. 로그와 MCP 응답의 HTML/스크립트는 실행하지 않고 텍스트로 표시한다.

## 데모 선행 수동 완료

데모 작업의 미완료 선행 모듈을 펼치면 「데모에서 이 모듈 완료」를 제공한다. 최초 계획·일시 중지·사람 판단 상태에 따라 비활성화 사유를 표시한다. 완료 이력에는 실제 실행/시험이 아닌 데모 수동 완료임을 명시한다. 실제 모드와 나머지 그룹에는 제공하지 않는다.

## 첫 화면 (D-38)

로컬 또는 SSH 터널 주소를 열면 접속 키 입력 없이 바로 대시보드가 나타난다. 연결 실패는 상태 표시로 안내하고 로그인 화면으로 전환하지 않는다. 새 업그레이드를 누르기 전에는 실행을 자동 생성하지 않는다.

## 오케스트레이터 표시 — 추가 설계, 미구현

- 상단/보조 영역에 「작업 조정」 상태와 마지막 검토 시각·대상 계획을 표시한다. 대기/검토 중/결과 있음/연결 실패/상태 확인 필요/한도 도달을 모듈 실행 상태와 구분한다.
- 제안 목록은 대상·이유·근거·다음 행동과 서버의 적용 결과를 보여준다. 「제안됨」「사용자 선택 대기」「명령 접수」「실행 완료」를 같은 완료 표시로 합치지 않는다. 오래된 제안은 「이전 기준 · 재검토 필요」로 표시하고 적용을 막는다.
- 모듈 상세에는 원본 보고와 별도의 조정 의견을 보여준다. 조정자의 해석으로 모듈의 실제 오류·리뷰·과거 실패를 덮어쓰지 않는다. v1 자료의 미제공 항목은 「보고되지 않음」으로 표시한다.
- 기존 실패 재시도 버튼을 유지한다. 자동 재시도 허용 전에는 제안의 수정 방향을 확인하고 사용자가 실행을 선택한다. 최초 계획/새 판단/최종 검토 외에 정상 단계마다 추가 승인을 요구하지 않는다.
- 판단 후보는 Jira 발행 여부와 분리하여 즉시 표시하고 영향 범위 보류 이유를 연결한다. 후보 접수/내부 판단 생성/Jira 연결/사람 결정/반영 완료를 구분한다. 조정 장애 시에도 사람이 후보를 검토할 수 있다.
- 설정에는 조정 활성화·호출 시간/횟수·재계획 한도·자동 재시도 한도와 wrapper 지원 상태를 표시하는 안을 추가한다. 새 값은 새 작업부터 적용하며 현재 UI에는 아직 없다.
- 진행도는 계속 서버 집계다. 조정 성공 횟수나 AI가 말한 퍼센트를 종합 진행도에 더하지 않는다. 일반 화면 새로고침으로 오케스트레이터를 호출하지 않는다.

표시 상태/권한 판단의 원천은 [오케스트레이터 명세](ORCHESTRATOR_SPEC.md)다. UI T-84와 실제 연동 T-85가 PASS가 되기 전 이 화면이 구현됐다고 안내하지 않는다.

## 수동 Claude 패키지의 현재 범위

이번 수동 Claude 패키지에서는 UI를 변경하지 않는다. 제안 JSON과 CLI의 WAITING_USER/BLOCKED/STALE은 검토 자료이며 대시보드에 반영된 상태가 아니다. 기존 화면의 사용자 명령을 통한 실행만 유지한다. [사용 안내](../agents/CLAUDE_ORCHESTRATOR_GUIDE.md)를 따른다.

환경 설정의 「고정 소스 커밋/해시」를 「소스 기준 (선택)」으로 변경했다. 자동 Git 기록과 데모 기준을 안내하며 예전 demo-os-v1 값은 자동 기록 버튼으로 비울 수 있다. 브리지 기본 경로·빈 항목 채우기·사용자 지정 값 보존·파일별 점검 표시를 제공한다. 기본 경로 그대로인 필드는 작업 폴더를 바꿀 때 같이 갱신한다. [설정 사용법](../agents/ENVIRONMENT_AND_BRIDGES.md)을 따른다.


## D-42 환경 설정 화면

에이전트·빌드 연결의 기본 선택은 내장 CLI 자동 탐지다. 작업/소스 폴더, 선택 지침 폴더, 빌드·검증·최종 통합 명령과 산출물 위치를 표시한다. CLI 경로/모델/선택 도구 해제/역할 파일 매핑은 접이식 고급 설정으로 둔다. JSON 실행 배열과 경로 채우기는 기존 브리지 모드에서만 보인다. 자동 탐지가 설치/로그인/실제 실행을 모두 의미하는 것으로 표시하지 않는다.

저장·JSON 가져오기/내보내기·재접속을 지원하고 기존 작업에는 소급하지 않는다. 조정 연결 실패는 실패 근거와 로그인 확인 후 연결 재시도 버튼을 표시한다. 실행 불명은 자동 재시도 버튼으로 풀지 않는다. 상세 설정 의미는 [환경 안내](../agents/ENVIRONMENT_AND_BRIDGES.md)를 따른다.

## D-44 GUI Test 설정·TC 목록·실행 순서

RQ-39 / T-109~111. Windows 단독과 Dashboard의 공통 `TestPage`에 적용한다.

- 연결 및 실행 준비, 실행 순서와 데모 시나리오, 소스 설정(Git 브랜치·TC 갱신·소스 기준), Suite 관리를 개별로 접고 펼친다. 제목 전체가 버튼이며 Enter/Space, 포커스 표시, 펼침 상태와 제어 대상의 접근성 속성을 제공한다.
- 접힌 제목에는 보드/COM, 선택 TC 수·속도, 현재 읽은 브랜치, 저장된 Suite 수를 표시한다. 실행·결과 영역은 접지 않는다. 접기만으로 입력이나 선택/기존 Run은 초기화하지 않는다.
- 최초에는 소스 설정만 접는다. 영역별 접힘 상태를 해당 브라우저/출처의 localStorage에 저장하며, 저장소 접근이 차단돼도 현재 화면의 접기 동작은 유지한다. 입력값 자체의 새로고침 저장을 새로 보장하는 기능은 아니다.
- TC 목록은 검색/유형 필터, 표시 개수, 폴더별 선택 개수와 별도 펼침 버튼, 체크박스, TC 이름·시간 제한·Single/Dual 배지로 구성한다. 일부만 선택한 폴더는 부분 선택을 표시한다. 검색·필터·폴더 접기는 선택을 제거하지 않는다. 빈 검색 결과에서 필터 초기화를 제공한다.
- 실행 순서는 TC 행을 드래그하여 앞/뒤 삽입 위치를 지정한다. 놓일 위치와 드래그 중인 행을 구분하고, 순서 번호 선택으로 마우스 클릭·키보드 대체 조작을 제공한다. 순서가 바뀌면 Suite 기준과 이전 Preflight 확인을 해제하고 다시 검증한다. 진행 중/완료 Run의 고정 순서는 변경하지 않는다.
- DB 스키마, 모의/실제 경계, 서버의 선행 순서·예약·게이트 검증은 유지한다. 두 빌드, 격리한 Windows Mock 브라우저 및 좁은 화면으로 확인하며 실제 Linux 통합/장비 인수와 구분한다.
