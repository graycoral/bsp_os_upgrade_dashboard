# 보드 커넥터 · 독립 Windows GUI 계획

상태: **SOURCE_IMPLEMENTED / LOCAL_MOCK_VERIFIED / WINDOWS_COMPANY_NOT_RUN**. 최초 사용자 지시(2026-11-12)는 독립 Windows GUI의 계획만 작성하는 것이었으며, 후속으로 **별도 Astra 리뷰 → 지적 반영 → Sol 구현**을 명시 승인했다. Mac에서 같은 GUI를 확인할 수 있어야 한다. 실제 SSH·보드·TC 실행과 게시/배포는 이 구현 지시에 포함하지 않는다. 기준 게시 커밋은 `6734c843c46e986ce5c35a0851c38ac009661b98`이다.

앞서 승인받아 작성하던 TC 제한시간·세션 영구 삭제 코드는 별도 미커밋 작업으로 보존한다. 필요한 연계 변경은 기존 diff를 확인한 뒤 최소 범위로 수행하며 그 코드와 GUI 구현 완료를 혼동하지 않는다. 집중 모의 48 PASS는 해당 중간 실행의 범위이며 현재 전체 제품/GUI 검증을 뜻하지 않는다. 기존 미커밋 전체 대시보드 설치 계획도 이 계획으로 대체하지 않는다.

## 1. 목표와 사용자 결정

사용자 확정: 최신 표시명은 **보드 커넥터**(최초 TEST BOARD CONNECTOR에서 변경), 형태는 **독립 Windows 창**이다. 새 frozen EXE를 만들지 않는 기존 방향을 유지한다. 실행할 때마다 의존성 설치·포트 입력·설정 재입력을 요구하지 않는다. 회사와 로컬은 같은 커넥터 코드와 실행 계약을 사용하고 환경 프로파일만 다르게 한다.

후속 사용자 요구: 작고 직관적인 GUI, 에러를 볼 수 있는 로그 창, 자동 검색한 COM 콤보박스, 파일/폴더 탐색 선택을 제공한다. 커넥터 연결 후 대시보드와 플러그인에 보드 현황을 별도 설정 없이 표시한다. TC 경로는 대시보드·플러그인의 공통 설정에서 관리하며 커넥터에서 중복 입력하지 않는다. Z: 공유 폴더 직접 실행과 현재 스냅샷 복사의 필요성도 비교한다. 직접 실행의 채택/기본값과 정확한 창 크기는 아직 제안이다.

## 2. 책임 경계

- **Windows GUI:** 연결/환경 설정, 보드·도구 탐색, 상태/진단, 저장 공간 표시, 대시보드 열기.
- **커넥터 실행 코어:** 기존 `Host`, 인증된 loopback API, Windows 프로세스/COM·배치 예약, 소스 고정, 퓨징·TC 실행과 종료 확인.
- **Linux 대시보드:** TC 선택·실행 요청, 전체/개별 제한시간 정책, 세션·결과·보고서와 명시적 영구 삭제의 사용자 조작.
- **회사 플러그인:** 기존 단일 실행 관리자/API로 실행을 요청하고 같은 실행 상태를 조회한다. GUI가 별도의 TC 배정자나 BSP Worker를 추가하지 않는다.

GUI의 연결 점검은 장치 목록·도구·HTTP 응답을 확인하는 읽기 전용 작업이다. 설정 저장/연결 시험으로 `reboot lkshell`, `fast`, `fastboot -w`, BAT 또는 TC를 실행하지 않는다. 실제 퓨징·TC와 최종 판정은 기존 서버 계약을 그대로 따른다.

### 대시보드·플러그인의 공통 연결

목표는 `대시보드 / 플러그인 → 공통 Linux API·단일 실행 관리자 → 연결된 커넥터 → 보드`다. 별도로 논의한 전체 대시보드 관리형 설치 설계와 동일하게 단일 실행 소유 원칙을 따른다. 커넥터 GUI는 Windows 연결과 장비를 관리하고 TC 소스·실행 정책을 따로 소유하지 않는다.

현재 전체 대시보드의 `backend/api/main.py`는 integration principal을 설정하지 않고 health도 단순 API 생존만 반환한다. 기존 `standalone/integration.py`에는 별도 인증·principal·Worker/identity health가 있고 기본 포트는 8767이다. `PluginClient`는 인증된 loopback endpoint와 고정 identity를 요구한다. 따라서 회사 대시보드 8765를 입력하는 것만으로 플러그인 연동이 현재 완료된다고 가정하지 않는다. 전체 호스트에 기존 인증/계약을 연결하는 작업과 회사 어댑터가 필요하다. 같은 runtime에 standalone Worker를 추가 기동하지 않는다.

Astra 코드 대조에서 확인한 필수 접점: `runtime.make_manager/live_manager`와 Worker는 기동 시 adapter를 고정하므로 등록 시 JSON만 저장해서는 재시작 없는 자동 보드 표시가 되지 않는다. API/Worker가 같은 영속 등록 상태를 읽는 안정된 facade와 Run별 runner identity/소스 고정 경계를 설계한다. 기존 Run의 실행 대상을 새 커넥터로 바꾸거나 실장비 미설정을 Mock로 대체하지 않는다. 자동 등록은 신뢰된 최초 설정/인증과 endpoint 왕복 검증을 통과해야 한다.

### 보드 현황 자동 표시

커넥터 최초 연결/등록 때 검증한 identity·실제 역방향 endpoint·보드 매핑·capability를 공통 백엔드에 연결한다. 대시보드와 플러그인은 이 공통 목록을 조회하며 각각 COM·runner URL·보드 ID를 다시 입력하지 않는다. 등록/endpoint 전달 방식은 기존 설정·토큰·SSH 경로와 호환되도록 설계할 추가 계약이며 현재 구현 완료가 아니다.

- 커넥터가 COM 장치의 추가/제거를 감지해 목록 revision과 마지막 확인 시각을 갱신하고, 클라이언트는 polling 또는 검증된 이벤트로 변경을 반영한다. 전송 방식과 주기는 구현 단계에서 고정한다.
- 보드별 표시: 이름, 소속 PC, COM, 포트 감지 여부, 예약/시험 중, 확인된 장비 응답, 마지막 확인 시각과 오류. 예약/Run 상태는 실행 관리자의 구조화된 기록에서 합친다.
- 현재 `Host.boards()`는 등록한 보드 중 COM이 열거된 항목만 반환한다. COM 감지는 보드 전원·정상 부팅·명령 응답의 증거가 아니다. 임의 probe/콘솔 읽기로 기존 TC 프롬프트를 소비하지 않는다.
- `Host.verify()`가 현재 보드 목록을 실행 가능 검사에 쓰므로 미연결 행을 그 목록에 단순 추가하지 않는다. UI용 전체 상태 조회와 실행용 가용 보드/검증 계약을 분리하고 미연결 보드 실행 거부를 회귀 시험한다.
- 등록 보드의 포트가 사라지면 행을 지우는 대신 미연결로 표시한다. 커넥터 heartbeat가 끊기면 마지막 목록은 오래된 정보로 표시하고 신규 실행을 막는다. 연결 소실로 기존 실행의 예약을 해제하거나 종료/PASS로 추정하지 않는다.
- 재연결은 같은 identity와 기존 Run을 복구하며 자동 재시험/재퓨징하지 않는다. 여러 커넥터의 COM 번호가 같아도 runner·board identity로 구분한다. 새 identity는 신뢰된 초기 등록 절차를 거치며 자동 발견만으로 신뢰하지 않는다.

## 3. 기술안과 배포

**제안:** Python + PySide6/Qt Widgets. Windows 데스크톱 UI와 비동기 작업을 구성하고 기존 Python 코어를 재사용한다. GUI 패키지의 정확한 버전·지원 OS·wheel 크기·해시·라이선스 파일은 구현 승인 후 검증한 조합으로 고정한다. 회사 실행 PC에서 pip로 GUI 의존성을 받게 하지 않는다.

PySide6 wheel에는 Qt 바이너리가 포함된다. 현재의 CPython embeddable 배포에는 Tcl/Tk가 없으므로 Tkinter를 추가 의존성 없는 대안으로 가정하지 않는다. 근거: [Qt 공식 설치 안내](https://doc.qt.io/qtforpython-6/gettingstarted.html), [CPython embeddable 안내](https://docs.python.org/3.12/using/windows.html#the-embeddable-package).

배포 형태는 편집 가능한 소스 + 전용 Python + 고정 의존성 폴더를 유지한다. GUI는 번들 Python의 GUI 실행 진입점으로 열고 PyInstaller EXE를 새로 생성하지 않는다. 기존 `launch.cmd`/진단 경로는 호환 진입점으로 유지할 방안을 검토한다. 소스 실행 사용자는 같은 사용자 환경을 재사용한다. 기존 외부 TC 전용 Python을 GUI Python으로 자동 교체하지 않는다.

GUI 진입 전 번들 무결성·필수 모듈을 확인하고, GUI 자체가 열리지 못하면 최소 Windows 오류 창과 로그 위치를 제공하는 bootstrap을 둔다. 누락·변조를 재설치 안내 한 줄로 숨기거나 실행 때마다 온라인 설치로 복구하지 않는다. 이 계획에서는 새 ZIP·EXE·바로가기를 생성하지 않는다.

## 4. 프로세스 구조와 수명

권장 구조는 **GUI 클라이언트 → 백그라운드 연결 관리자 → 기존 Host/SSH 자식**이다. 연결 관리자는 기존 CLI launcher의 역할을 분리한 것이며 Windows Service 설치를 기본 요구하지 않는다.

1. GUI와 독립된 연결 관리자가 사용자 home별 단일 소유 잠금·프로세스 생성 시각·runner identity·실제 포트를 보유한다.
2. GUI 재실행은 소유권을 검증해 같은 관리자에 연결한다. GUI 창을 여러 번 열어도 Host/SSH를 중복 생성하지 않는다.
3. GUI와 관리자 사이 제어 채널은 사용자 전용 인증이 있는 loopback IPC로 제한한다. 임시 포트는 OS로부터 소켓을 확보한 채 기동하고 실제 endpoint를 영수증으로 전달한다. 제어 자격 증명은 DPAPI/사용자 제한 경로로 관리하고 장비 API 토큰과 분리한다. 커맨드라인·로그에 넣지 않는다.
4. UI 스레드에서 SSH·공유 폴더 I/O·해시·HTTP 대기를 실행하지 않는다. 작업 큐와 Qt signal로 진행/실패/취소 상태를 전달한다.
5. **창 닫기**는 GUI 연결 해제다. 관리자·SSH·Host와 진행 중 퓨징/시험을 종료하지 않는다. 다시 열면 같은 상태를 복원한다.
6. **연결 종료**는 별도 조작이다. 활성 작업이 있으면 해당 정상 종료 정책에 따라 대기한다. 퓨징을 즉시 강제 종료하는 기능을 만들지 않는다.
7. 관리자/Host 장애 후에는 DB·identity·기존 receipt로 복구를 판정한다. UNKNOWN을 새 home·다른 포트로 우회하지 않는다.

Astra F5에 따라 GUI worker thread가 기존 launcher를 그대로 소유하는 구현은 피한다. 실제 별도 관리자 프로세스가 CLI helper를 재사용하고, 연결 종료는 RUNNING뿐 아니라 PAUSED/배치 예약/UNKNOWN/삭제 진행도 검사한다. SSH key/agent와 사전 OpenSSH 인증을 우선 지원하며 pythonw에서 대화형 prompt가 저절로 열린다고 가정하지 않는다. 필요하면 명시적 인증 콘솔 helper를 사용한다. SSH -L 포트는 SSH가 바인딩하므로 probe 이후 경쟁을 별도로 처리하고 실패를 숨기지 않는다.

기존 `LaunchLock`, `process_identity`, `read_active`, `read_startup`, `Host`의 준비 확인과 예약 규칙을 재사용한다. 단순 PID 존재·포트 점유·프로세스 생성만으로 기존 실행에 임의 연결하지 않는다. 프로세스/설정/버전이 다른 점유자는 구분해 안내한다.

## 5. 화면 구성

기본 창은 **연결 / 환경설정 두 탭**과 하단의 접을 수 있는 **로그 창**으로 구성한다. 별도 보드/로그/저장 공간 대형 화면을 늘리지 않고 연결 탭의 보드 목록과 설정의 접힌 상세 영역에 배치한다. 초기 크기는 약 820×560을 검토하되 확정값은 아니며 Windows 배율·작은 화면에서 버튼/오류가 잘리지 않도록 크기 조절과 필요한 영역 스크롤을 지원한다. 원시 JSON·해시·전체 포트 설정은 기본 화면에 나열하지 않는다.

각 보드 행은 작은 상태등·이름·COM·짧은 상태 문구를 표시한다. 초록=연결됨/대기, 노랑=시험 중, 빨강=오류, 회색=미연결을 제안한다. 확인 중/종료 불명은 문구로 명확히 구분하고 실행 가능으로 표시하지 않는다. 색상만으로 의미를 전달하지 않으며 상태등으로 TC 결과 PASS를 표시하지 않는다. 시험 중/예약 상태는 공통 실행 관리자와 커넥터 기록에서 가져온다.

Astra F7에 따라 같은 Qt view/controller에 실제 adapter와 mock adapter를 주입한다. --preview는 초기 진입점부터 격리된 임시 home을 사용하며 기존 설정/DPAPI/serial/SSH/subprocess 호출을 금지하는 시험을 둔다. offscreen 시험과 별도로 Mac에서 실제 창을 열고 탭·상태등·로그·파일 선택/취소·작은 크기를 확인한다.

Mac에서는 같은 Qt 화면을 열 수 있는 명시적 미리보기 모드를 제공한다. 모의 보드 연결·시험 중·분리·오류와 로그를 재현하고 미리보기임을 표시한다. 미리보기에서 Windows DPAPI·COM·fastboot·SSH·BAT·실제 TC나 회사 서버를 호출하지 않는다. 화면 미리보기 통과와 Windows 실장비 인수를 별도 기록한다.

### 연결 현황

상단에 프로파일·전체 준비 상태·`연결`·`연결 종료`·`대시보드 열기`를 배치한다. 하단 상태는 다음 순서로 각각 표시한다.

1. 로컬 커넥터 기동: Python/설정/DB/잠금/API identity.
2. SSH: 서버 연결·호스트 인증·키/사용자 인증·포워딩 확보.
3. Windows → Linux 대시보드: 실제 HTTP 응답 확인.
4. Linux → Windows 커넥터: 역방향 API·인증·identity/capability 확인.
5. 보드 준비: 등록 COM 가용성. 실제 보드 이미지 동일성이나 TC PASS를 뜻하지 않는다.

커넥터의 `Application startup complete`는 첫 단계만 완료한 상태로 표시한다. 읽기 전용 연결 왕복을 확인하기 전 전체 초록색/연결 완료로 표시하지 않는다. TC 시작 가능 여부는 기존 대시보드 Preflight가 최종 검사한다.

### 연결·환경 설정

- Linux SSH 서버·계정·SSH 포트와 대시보드 포트를 분리한다. 이 사용자의 회사 예시는 원격 대시보드 **8765**다. 전체 사용자의 기본 포트를 8765로 바꾸는 결정은 아니다.
- 로컬 브라우저 터널·로컬 커넥터·원격 역방향 포트는 고급 영역에 표시한다. 자동 대체되는 것은 기존 정책의 로컬 포트이며 원격 서비스 포트는 자동 변경하지 않는다.
- 기본값/저장값/CLI override/실제 사용값을 구분한다. 자동 선택된 `60892` 같은 주소를 사용자가 옮겨 적게 하지 않는다.
- TC 소스/이미지 경로는 공통 Linux 설정이 소유한다. 커넥터에서 TC 폴더를 필수로 다시 입력하지 않는다. 외부 TC Python과 SSH 키 등 Windows 파일이 필요한 설정은 탐색기로 선택한다. 저장은 검증·미리보기·원자 교체로 수행하고 기존 추가 필드/백업을 보존한다.
- SSH 인증은 기존 OpenSSH·키/agent를 우선 사용한다. 비밀번호/키 암호 등 상호작용이 필요한 환경의 표준 OpenSSH 인증창 연계는 별도 구현/인수 항목이다. GUI가 비밀번호를 일반 JSON/로그에 저장하거나 인증 성공을 추정하지 않는다.
- GUI에서 connection/type 선택 아래 불필요한 `+`를 재도입하지 않는다. 공통 TC UI의 전체 선택 체크박스는 이름 헤더와 같은 행 안에서 이름 바로 옆에 배치한다.

### 보드·도구

등록 보드 목록, COM·노드, 연결 가용성, fastboot 경로와 읽기 전용 장치 목록을 표시한다. `reboot lkshell`/`fast`는 실행 코어의 공통 명령이고 사용자 입력란으로 반복하지 않는다. 개행·baud·준비 문구는 공통값과 보드별 예외를 구분한다.

COM은 `serial.tools.list_ports` 기반 자동 검색 결과를 콤보박스로 제공한다. `COM7 · USB 장치 설명` 형태로 표시하고 장치 갱신과 수동 새로고침을 지원한다. 장치 하나라는 이유로 기존 보드를 다른 COM에 자동 재매핑하지 않는다. 미연결 저장값은 사라지지 않고 미연결로 표시하며, 여러 보드/COM 대응은 최초 선택으로 확정한다. 열거만으로 점유/정상 응답을 판정하지 않고, 검색 중 포트를 임의 개방하거나 콘솔 데이터를 읽지 않는다. 연결/시험 중 설정 변경은 현재 실행에 반영하지 않고 안전한 적용 시점에 검증한다.

파일은 Windows 기본 파일 선택창, 폴더는 폴더 선택창을 사용한다. 네트워크 드라이브·UNC와 기존 경로에서 시작하는 탐색을 지원하며 직접 붙여넣기도 허용한다. Linux 경로가 필요한 설정은 공통 백엔드의 허용 루트 내 서버 경로 선택 기능으로 연결한다. Windows 탐색기 결과를 Linux 경로로 오인해 저장하지 않는다. 서버 선택 API는 현재 지원 여부를 확인해 추가할 계획이며 새 기능이 이미 존재한다고 가정하지 않는다.

fastboot의 `fastboot init success`와 BAT 후 `login :`를 구간별 출력으로 표시한다. fast 이전 lkshell 준비 프롬프트는 아직 실제 값이 미확인이다. root 로그인 역할은 기존 TC 계약에 두며 GUI가 먼저 로그인해 TC가 기다리는 프롬프트를 소비하지 않는다.

### 진단·로그

실패한 구간과 정확한 대상 주소·포트·오류 코드·시각·대기시간을 표시한다. `Connection refused`를 무조건 포트 번호 변경으로 안내하지 않는다. 로컬 실패/SSH 인증/정방향/역방향/TC 제한시간을 별도로 판정한다. 안전한 로그 열기·마스킹된 진단 묶음 내보내기를 제공하고 토큰/암호/환경 전체는 내보내지 않는다.

로그 창은 실시간으로 시각·단계·중요도·오류 코드·설명/조치를 표시한다. 오류 시 하단에 요약과 `로그 보기`를 표시하고, 펼친 창에서는 오류 필터·검색·선택 복사·로그 폴더 열기를 제공한다. 같은 오류 반복은 건수로 묶고 화면 버퍼와 파일은 크기/보관 정책으로 제한한다. UI 창을 닫아도 백그라운드 로그를 보존한다. TC stdout/stderr는 Run과 연결해 조회하고 연결 로그와 출처를 구분한다. 기본 작은 창에 전체 로그/traceback을 쌓지 않으며 비밀정보 마스킹을 표시/저장/내보내기에 동일 적용한다.

### 저장 공간

Astra F6에 따른 첫 GUI 구현은 저장 공간 사용량/보호 이유 조회와 기존 중앙 timeout/삭제 기능 연결을 우선한다. 새 자동 정리 정책은 별도 미완료 요구로 남기고 임의의 24시간 기본값을 활성화하지 않는다. 공유 직접 실행 원본은 어떤 정리/영구 삭제에서도 제외한다.

TC 실행 사본·이미지/공유 캐시·로그/DB 사용량, 실행 중 보호량, 정리 가능량과 마지막 정리 결과를 보여준다. 보관기간/용량 상한은 설정 정책을 확정한 뒤 적용한다. 기본 24시간 보관은 이전 대화의 **제안**이며 확정값이 아니다.

자동 정리는 종료 확인·활성 Run/유효 준비/복구 참조를 기준으로 한다. RUNNING·대기·PAUSED·UNKNOWN과 참조 확인이 불가능한 대상은 보호한다. 원본 공유 TC/이미지·사용자 Python·인증 설정은 자동 삭제하지 않는다. 정리해도 공간이 부족하면 신규 작업을 차단하고 이유를 표시한다.

세션의 **시험 기록까지 영구 삭제**는 사용자가 별도로 승인한 조작이다. 대시보드에서 완료/취소·제어권·예약/동기화/참조·원래 Windows 실행을 확인하고, 해당 커넥터 사본과 DB 기록 정리가 확인된 뒤 완료 처리한다. 자동 스냅샷 정리와 구분한다. 이미 내보낸 파일·외부 백업까지 삭제됐다고 표시하지 않는다.

회사 설정을 가져올 수 없을 때만 미설정 필드를 보인다. 프로파일은 신뢰된 회사 배포 경로로 제공하고 비밀을 내보내지 않는다. 연결/재연결은 기존 서비스를 재사용하며 이미 실행 중인 대시보드를 새로 띄우거나 매번 의존성을 설치하지 않는다. endpoint 자동 등록은 인증된 왕복 확인이 필요하다. 회사 plugin 코드가 없는 이 저장소에서 회사 접점이 모두 자동 완성됐다고 주장하지 않는다.

### TC 경로의 소유와 실행 요청

TC 소스는 공통 서버가 한 번 관리하고 실행 요청에 신뢰된 소스 참조·상대 TC 경로·고정 명령/보드/제한시간을 담는다. 커넥터는 실행 시 Windows 접근 경로를 전달받아 검증하며 TC 폴더 선택을 필수로 요구하지 않는다. Linux `/srv/tc`와 Windows `Z:\\TC`/UNC는 다른 경로이므로 공통 프로파일에 소스별·runner별 대응 관계를 최초 한 번 제공하거나 회사 프로파일에 포함해야 한다. Linux 경로에서 임의 추측하지 않는다. 커넥터 파일 선택 UI를 경로 등록 도구로 사용할 수 있으나 같은 값을 독립된 두 설정으로 저장하지 않는다.

허용 소스/경로 이탈·링크·보드 예약·인증은 커넥터에서도 검증한다. 입력 간소화를 임의 절대 경로/셸 명령 허용으로 구현하지 않는다. 기존 `Host`는 고정 `source_root`를 요구하므로 새 방식은 계약/capability·호환 어댑터와 함께 도입한다. 위 표의 Windows `source_root` 재사용은 legacy 호환 범위이며 새 방식의 TC 소유권을 뜻하지 않는다. 기존 요청/기록을 보존한다.

최초 GUI는 TC 소스/보드 설정이 없어도 열리고 설정·포트 검색·미설정 상태를 표시할 수 있어야 한다. 현재 Host는 소스 루트와 최소 보드가 없으면 기동하지 못하므로 bootstrap/상태 조회와 실행 준비를 구분한다. 소스 미준비 상태에서 연결 성공을 TC 실행 가능으로 표시하지 않으며 구조화된 미설정 오류로 거부한다.

### Z: 직접 실행과 스냅샷

현재 `Host.catalog()`는 목록 조회에도 임시 스냅샷을 만든다. 각 TC Attempt는 `Host.start()`에서 `snapshot()`/`copy_snapshot()`으로 소스 트리를 다시 복사한다. `execution/source.py:read_source()`는 제외 경로 외 파일을 합계 최대 128MiB까지 bytes 사전에 보관하므로 RAM 사용과 복사 I/O가 있다. venv/숨김 경로 등은 제외한다. 별도 이미지 스트리밍과 TC 메모리 동작을 혼동하지 않는다.

복사는 실행 자체의 필수 조건이 아니라 동일 입력/실행별 쓰기 공간을 위한 현재 계약이다. Windows가 이미 공유 폴더를 읽는 경우 다음 모드를 검토한다.

| 방식 | 장점 | 필요한 계약 |
|---|---|---|
| 공유 폴더 직접 실행 | Z:/UNC에서 기존 Python/cwd로 실행; Windows TC 사본/전송 생략 | 공통 경로 대응·허용 루트, 접근/원본 변경 오류 기록, 동일성 보장 한계 명시 |
| 고정 사본 실행 | 원본 변경과 분리된 입력·재시도 및 쓰기 공간 | 반복 전송/매 Attempt 복사 최적화, 작은 단위 읽기·캐시 참조/정리, TC 쓰기 격리 |

공유 접근이 준비된 회사 TC에는 직접 실행을 제안하되 채택/기본값은 리뷰 결과로 기록한다. 실행 전후 해시만으로 실행 중 변경/원복이나 늦은 import를 완전히 막을 수 없다. 가변 공유 폴더를 immutable snapshot과 같은 보장으로 표시하지 않는다. 고정 버전이 필수면 서버의 변경 불가능한 버전 폴더 또는 기존 복사를 사용한다. 변경을 확인하면 정상 PASS로 숨기지 않고 소스 변경 오류로 기록한다. TC의 소스 폴더 쓰기·cwd/상대 데이터 의존성을 확인한다. 기존 plugin preview/token의 소스 고정과 퓨징 이미지 사본은 별도 계약으로 유지한다.

Astra 권고에 따라 기존 RQ-56/60의 고정 사본 기본값과 preview/token 보장은 유지하고, 직접 실행은 명시적 opt-in capability/Run 소스 모드로 분리한다. 새 모드가 없는 구 실행기나 과거 Run의 의미를 바꾸지 않는다. 사용자에게 매 TC 재승인을 요구하지 않고 공통 소스 프로파일에서 한 번 선택한다.

Z:는 커넥터 실행 사용자의 로그온 문맥에서 접근 가능해야 한다. UAC로 다른 세션에서 실행하면 매핑이 보이지 않을 수 있다는 [Microsoft 안내](https://learn.microsoft.com/en-us/troubleshoot/windows-client/networking/mapped-drives-not-available-from-elevated-command)를 따른다. 불필요한 관리자 실행 없이 실제 실행 계정으로 경로를 검사하고, 접근 가능한 UNC도 사용할 수 있다. 매핑/정책/자격 증명을 임의 변경하지 않는다.

## 7. 연결 실패 판정 계약

| 단계 | 예시 | 표시/다음 행동 |
|---|---|---|
| 로컬 기동 | 모듈 누락, 설정 오류, 시작 receipt 불일치 | 구체 단계·파일/로그 위치. 구동 중 대시보드를 다시 띄우지 않음 |
| 포트 | 본인 실행 중 / 다른 프로세스 점유 | 본인 실행은 소유 검증 후 재사용; 타 프로세스 종료 금지 |
| SSH 인증 | 인증 대기/실패, host key 불일치 | 표준 인증 절차 안내. 자동 신뢰 등록/우회 없음 |

| 역방향 | Linux에서 커넥터 응답 실패 | 실제 Windows 포트·SSH -R·Linux 연결 URL·token/identity 확인 |
| 목록 조회 | 공유 폴더 지연 | 목록 읽기 제한시간과 진행 표시; TC 실행 제한시간과 분리 |
| TC 실행 | `TEST BOARD CONNECTOR TIMEOUT` | 해당 실행에 고정된 TC 시간 표시; 다음 실행 설정 변경으로 연계 |
| 복구 | 종료 불명/UNKNOWN | 근거 확인 전 재실행·재퓨징·기록 삭제를 차단 |

현재 API/프로세스 생존만으로 end-to-end 연결 성공을 표시하는 접점을 보완한다. 기존 Linux 진단 응답에 필요한 identity/roundtrip 근거가 부족하면 최소 읽기 전용 진단 확장을 정의하고, 회사 어댑터가 같은 의미를 제공하도록 문서화한다. GUI가 로그 문장을 파싱해 장비 PASS/예약 해제를 확정하지 않는다.

## 9. 구현 단계와 완료 조건

1. **설계 확정:** 본 계획, GUI 화면 책임·설정 소유·종료 동작·실제 회사 SSH 인증 방식을 확인한다. 관련 RQ/D/T/PORT는 구현 단위가 확정될 때 등록한다.
2. **공통 기동 코어 분리:** 기존 CLI 회귀를 유지하면서 상태/명령 인터페이스·단일 관리자·오래된 receipt 거부·프로세스 수명을 모의 시험한다.
3. **데스크톱 GUI:** 저장 설정 불러오기·연결/종료·상태·대시보드 열기부터 붙인다. UI 응답성/창 재열기/중복 실행을 검증한다.
4. **진단/설정/보드:** 단계별 왕복, 포트 충돌, SSH 인증창, COM/fastboot 읽기 전용 탐색·저장·취소/실패 복구를 검증한다.
5. **시간/세션/저장 공간:** 승인된 기존 기능의 최종 계약을 연계하고 원본/보호 스냅샷·영구 삭제를 구분한다. 자동 정리의 보관기간·상한은 별도 확정한다.
6. **오프라인 전달/회사 인수:** 고정 버전·해시로 Windows x64 오프라인 실행/복원을 검증한 뒤 회사의 실제 SSH·COM·TC·보드 증거를 확보한다.

회귀 항목은 설정 재사용·토큰 격리·반복 실행·중복 방지·Windows 프로세스 종료·예약·UNKNOWN·BSP 게이트·TC 최종 판정·퓨징 중 비강제 종료다. GUI 구현으로 이 규칙을 약화하지 않는다.

## 10. 검증 계획과 현재 상태

모의 검증: GUI 한 번 실행/재열기/복수 클릭, 느린 시작과 pending SSH 인증, 네 구간별 timeout/refused/auth 오류, 실제 URL 전달, 설정 취소/원자 저장 실패/기존 추가 필드 보존, UI 종료 후 작업 유지, 관리자 장애·재시작·UNKNOWN, 읽기 전용 검색, 삭제 확인/부분 실패 재시도, 저장 공간 부족/보호 대상 거부.

회사 인수: 실제 Windows 정책·GUI wheel/runtime 호환, OpenSSH 키/agent·대화형 인증, 회사 서버 **8765**의 실제 응답과 역방향 identity, 공유 폴더/외부 TC Python/COM/fastboot, 독립 창 종료·재열기와 시험/퓨징 지속을 확인한다. 회사 대시보드의 `+`와 체크박스 배치는 회사 소스/화면에서 별도 확인한다. 원본의 계획/모의 PASS로 회사 결과를 대체하지 않는다.

현재 GUI 제품 시험·Windows 인수는 **NOT_RUN**, Astra 독립 리뷰는 **CHANGES_REQUESTED**이며 F1~F7을 이 계획에 반영했다. 제품 구현의 승인/시험을 뜻하지 않는다. 후속 승인에 따라 Astra가 독립 세션에서 설계를 검토하고 지적을 반영한 뒤 Sol이 구현한다. Mac GUI 미리보기, 공통 보드 상태/설정 소유, 경로 선택, 중복 실행·통신 단절·직접/고정 소스 보장 차이를 검증한다. 실제 회사 장비 실행과 커밋/푸시는 별도 지시 범위다.
