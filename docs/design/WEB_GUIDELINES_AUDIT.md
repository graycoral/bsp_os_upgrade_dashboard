# UI 접근성·성능·UX 점검 · 2026-11-04

사용자 요청에 따라 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)의 최신 규칙으로 Dashboard, 공통 GUI Test, 다이어그램 UI를 점검한다. RQ-19/20/38/39/50의 표시·조작 품질 보완이며 서버 실행 정책이나 데이터 계약 변경은 아니다.

## 수정 우선순위와 인수 조건

1. 모달: 배경 조작을 차단하고 실제로 사용할 수 있는 컨트롤 사이에서 키보드 포커스를 유지한다. Escape/닫기 후 호출 버튼으로 복귀한다. 요청 실패는 열린 모달 안에서 읽을 수 있어야 한다.
2. 입력 유실·오저장: 모든 설정 저장/점검 경로에 같은 폼 유효성 검사를 적용한다. 잘못된 JSON을 입력한 상태에서 이전 유효 값을 대신 저장하지 않는다. 실패 시 입력을 유지하고 저장하지 않은 변경은 브라우저 이탈 전에 알린다.
3. 실행 제어: 테스트 중단은 대상 Run을 명확히 확인한 뒤 실행한다. 확인 취소는 요청을 만들지 않으며 선택이 바뀐 다른 Run에 적용하지 않는다. 설정 모듈 삭제도 확인 또는 복구 수단을 제공한다.
4. 키보드 접근: 파일 가져오기는 키보드로 실행할 수 있고, TC 실행 순서는 드래그 외에도 버튼으로 바꿀 수 있어야 한다. 검색 밖 선택과 전체 실행 순서를 보존한다. 본문 건너뛰기와 명확한 포커스 표시를 제공한다.
5. 의미 있는 상태: 진행률은 전체/단계/모듈 이름을 함께 제공한다. 대상 없음과 0%를 구분한다. 비동기 오류·결과를 보조 기술에 알린다.
6. 탐색: 사이드바는 실제 링크를 사용하고 선택 화면을 URL에 보존한다. 새로고침·뒤로/앞으로 가기와 기존 `guiExecution` 보기 선택이 동작한다.
7. 목록 비용: 접힌 TC 폴더의 하위 행을 만들지 않고, 선택·순서·ID 조회는 재사용 가능한 자료구조로 처리한다. 긴 목록의 화면 밖 렌더링 비용을 줄이며 검색/선택/키보드 동작을 보존한다.

## 검증 경계

main 통합 후 이 감사의 시험 ID는 T-153~155, 결함 ID는 REG-0041이다. 브랜치별 중복 ID를 해소한 것이며 main의 기존 T-150~152/REG-0039~0040은 유지한다. 통합 결과의 검증은 [별도 실행 기록](../testing/runs/20261104-web-guidelines-main-merge.md)을 따른다.

브라우저 시험은 합성 응답 또는 격리된 Mock runtime을 사용한다. 실제 BSP·모델·Jira·회사 공유 폴더·장비 작업을 실행하지 않는다. Dashboard 빌드와 GUI Test 단독 빌드를 모두 확인하며, 공통 UI 파일은 `gui_test`만 배포해도 동작해야 한다.

상세 설계는 GPT-6 Astra High, 구현·독립 리뷰는 서로 다른 GPT-6.1 Sol High 세션, 시험 작성은 GPT-6.1 Sol Medium, 실행·보고는 GPT-6 Luna Low로 분리한다. 실제 결과와 남은 제약은 [실행 기록](../testing/runs/20261104-web-guidelines-audit.md)에 기록한다.
