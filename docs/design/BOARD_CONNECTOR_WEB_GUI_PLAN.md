# 보드 커넥터 GUI 개선 · 구현 전 검토안

2026-11-14. 대상: RQ-63~66의 기존 보드 커넥터 화면과 RQ-65 Windows 실행 진입점. 사용자 최종 지시는 **웹 기본 전환**이며 Qt는 명시적인 호환 옵션이다. Astra xhigh가 최초 opt-in 검토 뒤 사용자 지시를 반영한 기본 브라우저 전환을 추가 검토해 설계를 APPROVED했다. 제품 구현 후 독립 리뷰는 사용량 제한 실패 이력을 보존한 뒤 재개했고, 네 지적을 수정해 웹 GUI 변경 범위 APPROVED를 받았다. 실제 리뷰 근거는 [리뷰 기록](../testing/runs/20261114-connector-web-review.md)을 따른다. 로컬 소스 구현/모의 검증 단계이며 실제 Windows/회사 인수를 뜻하지 않는다.

## 실행 위치와 책임

- Linux 플러그인은 기존 서비스/Worker에 작업을 요청한다. 기존 실행 소유권과 구조화된 기록을 재사용한다.
- Windows 사용자는 Z: 공유 폴더 또는 로컬 소스 폴더의 `board-connector.cmd`를 실행한다. 파일 저장 위치가 Linux여도 실행 주체는 Windows다.
- Windows의 기존 Manager/Host가 SSH·COM·USB·TC·플래싱을 수행한다. GUI를 웹으로 바꾸기 위해 별도 실행 관리자나 Worker를 만들지 않는다.
- 브라우저는 Windows 로컬 화면이다. GUI 앱 설치는 생략할 수 있지만 Windows 실행부·Python·TC 의존성·드라이버는 여전히 필요하다.
- 기본은 브라우저 화면이며 `--ui qt`로만 기존 Qt 호환 화면을 연다. 브라우저를 닫아도 작업·연결은 유지하고 새로 열면 기존 Manager에 접속한다. 기본 경로는 Qt 검사/설치를 하지 않는다.
- Z: 실행 소스를 버전별로 Windows 로컬에 복사하는 배포 캐시는 별도 설계 대상이다. 이번 화면 구현만으로 캐시 배포가 완료됐다고 표시하지 않는다.

## 화면과 조작

1. 첫 화면에 현재 연결, 등록/감지/실행 보드 수, 선택 보드의 작업과 제어권, 지금 가능한 행동을 표시한다.
2. 보드는 선택을 유지하는 목록으로 표시한다. COM 감지를 전원·부팅·시험 통과로 표현하지 않는다. UNKNOWN/오래된 상태를 정상과 구분한다.
3. COM 멀티플렉서는 기존 단독 물리 포트 소유와 TC·관찰·PuTTY 구독을 그대로 사용한다. 수동 제어 시작/반납과 PuTTY 조회/제어 차이를 화면에서 설명한다. 버튼 비활성 사유를 표시한다.
4. 환경설정은 서버·TC Python·보드 매핑을 중심으로 구성하고 SSH 키/포트·기존 native RX·PuTTY 경로는 상세 설정에서 제공한다. 보드 수 감소/재증가, 변경 취소, 알 수 없는 기존 설정·통신 플래그를 보존한다.
5. 보드 콘솔·TC 출력·연결·공통 오류를 구분한다. 검색·오류 필터·복사·로그 폴더 열기와 경로 조회를 제공한다. 로그는 한도를 두고 사용자가 과거 내용을 읽는 동안 자동으로 아래로 이동시키지 않는다.
6. 설정 저장·연결·제어 요청은 대기 상태와 완료/실패를 보여준다. 폴링을 겹치지 않고 편집 중인 폼을 상태 갱신으로 덮어쓰지 않는다.
7. 연결 실패는 단계, 확인된 사실, 영향, 재시도/복구 행동으로 설명한다. 401만으로 인증 원인을 단정하지 않으며 구버전 혼용 등은 확인 항목으로 표시한다.

## 브라우저 경계와 동시 요청

- 기존 인증된 비브라우저 IPC와 별도의 브라우저 경로를 둔다. 기존 Host/등록 API의 loopback·Origin 거부를 완화하지 않는다.
- GUI를 여는 부트스트랩만 기존 IPC로 단기 일회성 티켓을 요청한다. 관리자 DPAPI bearer는 브라우저·URL·JS·로그에 제공하지 않는다.
- 티켓을 브라우저 세션으로 교환하고 HttpOnly/SameSite 쿠키, 정확한 loopback Host/Origin 검증과 쓰기 요청의 CSRF 검증을 적용한다. 서로 다른 home/port의 Manager 세션을 혼용하지 않는다.
- 정적 자산과 API는 같은 origin에서 제공하고 외부 CDN·임의 파일 제공·임의 명령 실행은 추가하지 않는다.
- 연결·종료·설정 저장의 검사와 실행은 같은 제어 잠금으로 직렬화한다. 설정 revision을 비교해 여러 탭의 오래된 폼 덮어쓰기를 거부한다.
- 브라우저 파일 입력은 Windows 전체경로 선택을 대체하지 않는다. 네이티브 선택 접점 또는 명시된 수동 전체경로 입력/Qt 호환 경로를 제공한다.

## CMD 진단

원인 미확정인 회사 증상: 같은 PowerShell 위치에서 CMD는 경로 오류, CMD의 Python 명령을 직접 입력하면 실행됨. REG-0030의 과거 오진을 반복하지 않는다.

- 단계별 코드로 CMD 시작·소스 접근/누락·Python 후보/선택·준비/GUI 실패를 구분한다. 가능한 경우 Windows 로컬에 진단 로그를 둔다.
- AutoRun을 끈 CMD로 재진입하되 스크립트 실행 전에 발생한 최초 AutoRun 오류까지 제거한다고 주장하지 않는다. 이 경우 `cmd.exe /d /c .\board-connector.cmd` 확인을 안내한다.
- 소스는 CMD 기준 절대경로로 호출한다. 자동 드라이브 재연결·레지스트리 수정·관리자 승격·사용자 설정 삭제를 하지 않는다.
- 사용자가 직접 성공한 python.exe를 명시할 수 있게 하고, 선택된 Python 경로·버전·64비트 여부를 확인한다. 실패한 후보를 숨긴 채 Python 미설치로 단정하지 않는다.
- `--diagnose`는 설치·GUI·Manager·SSH·장비 실행 없이 파일/인터프리터/기존 환경 상태만 검사한다.

## 검증과 산출물

기존 launcher/connector/multiplexer/layout 기준 회귀는 `.local-reports/20261114-connector-web-review/baseline-unrestricted.log`에서 76 PASS/5 Windows SKIP다. 앞선 샌드박스 소켓 제한 실패는 baseline.log에 보존한다. 이 결과는 변경 후 검증이 아니다.

필수 후속 시험: 브라우저 인증·CSRF·티켓 만료/재사용·다른 Manager 쿠키·Host/Origin 위조·IPC 보존·본문 한도, 설정 충돌/연결 경쟁·값 보존, COM 제어권·UNKNOWN·중복 클릭·재접속·탭 종료, 브라우저 편집/필터/스크롤·반응형/키보드, 별도 폴더·wheel/소스 패키징 자산, Windows CMD 공백/기호/줄바꿈/다른 cwd·인자/실패 코드·진단 모드다.

최종 진입 문서는 [사용·오류 해결 가이드](../gui_test/TEST_BOARD_CONNECTOR_GUI.md), 회사 적용은 [PORT-009](../porting/PORT-009.md)다. 독립 리뷰와 변경 후 시험은 별도 실행 기록으로 연결한다. 실제 Windows Z:/UNC·COM·USB·SSH·회사 플러그인 인수는 사용자가 수행하며 증거 전 NOT_RUN이다.
