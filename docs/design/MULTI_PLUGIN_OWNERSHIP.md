# 여러 플러그인의 보드 사용 및 Agent Monitor 작업 선택

RQ-87 · T-324 · PORT-021. 기준 377832f. Windows Host 한 대의 보드 실행은 한 번에 하나다. 회사 GUI Test 서비스가 관리하는 별도 예약 계약은 유지한다.

## 계정 등록과 신뢰 경계

개인 설치의 기존 동작과 마이그레이션을 위해 Windows 운영자가 공유 모드를 명시적으로 활성화한다. 공용 Linux에서는 최초 플러그인 접속 전에 활성화한다. 활성화한 Host는 등록되지 않은 요청을 기본 거부하고 기존 v1 쓰기나 대시보드 프록시로 우회할 수 없어야 한다. 공유 모드의 기존 Host 관리 경로는 Windows 로컬 운영자 자격으로만 허용한다. 관리자 키는 SSH 역방향 포트로 발급하지 않는다. 공유 모드 전환은 유휴 상태에서 수행하고 재시작 후에도 유지한다. 자격 데이터가 손상되면 차단한다. Windows에서 발급한 계정별 자격을 대상 Linux 계정에 한 번 안전하게 전달한다. argv·URL query·로그에 비밀값을 쓰지 않는다. Linux에서 파일은 소유자 전용, Windows에서는 기존 사용자 전용 저장 방식을 따른다. 계정명, 소스 경로, peer hello 또는 임의 URL은 권한 근거가 될 수 없다.

## 작업 수명과 Host 계약

회사가 새 작업을 열 때 안정적인 작업 핸들을 발급하고 같은 작업 재개 시 다시 사용한다. 명령마다 실행되는 Python 프로세스, PID, cwd, 계정 공용 peer ID는 작업 ID로 사용할 수 없다. Host는 계정 자격과 별도 작업 자격을 검증한다. Linux는 명시적인 작업 선택을 작업별 파일에 원자적으로 보관한다. 등록 재시도와 동시 생성에도 소유권이 바뀌지 않는다. 독립 창은 같은 폴더에서도 각각 다른 작업을 생성한다. 같은 Unix 계정 내부의 파일 접근은 OS 보안 경계로 보장하지 않는다.

Run 수락과 소유 작업·모니터 식별·멱등 매핑은 하나의 트랜잭션이다. 요청 전 자격·멱등키를 보관하고 응답 유실 후 동일 작업의 재전송은 기존 Run을 돌려준다. 제어 요청은 Run 상태 전이와 같은 잠금 범위에서 현 소유자를 확인한다. 일시정지, 취소, 재개, 삭제, 재실행, reconcile, 분석 claim 및 결과, 로그·증거·스냅샷까지 서버가 접근을 판정한다. 다른 작업에는 점유 여부만 공개하고 다른 계정의 경로·로그·과거 목록·설정이 새지 않게 한다. Run을 시작한 작업의 실행 설정·TC 선택을 고정한다. COM, 보드 매핑, 재시작, 공유 설정은 운영자가 관리한다. 예전 실행은 자동 귀속하지 않는다. 운영자의 명시적 인계는 이전 제어권을 무효화하고 시각·이전/새 소유자를 기록한다. 단절과 타임아웃으로 장비를 반납하지 않는다. 계정 폐기 후에도 실행 기록은 남긴다.

## 연결 표시와 모니터 선택

connect --watch는 계정·포트별 감시 하나라는 PORT-017 계약을 유지한다. 각 작업은 독립 등록 및 최근 활동을 보고한다. UI는 마지막 보고 시간과 Run 소유자를 구별한다. Windows에서 처음 열면 활성 Run 소유 작업, 없으면 조회 가능 작업 한 개를 바로 선택하고 여러 개면 목록에서 선택한다. 이미 열린 화면은 작업을 고정한다. Linux 플러그인의 열기 명령은 항상 명시한 작업을 연다. 목적지 미등록·오프라인·권한 부족이면 그 원인을 표시하고 다른 모니터를 대신 열지 않는다.

모니터 목적지는 운영자가 승인한 프로필의 모니터 인스턴스와 검증된 루프백 포워딩으로 해석한다. 플러그인 입력으로 임의의 포트나 URL을 열지 않는다. 등록된 설치별 모니터 포트가 다르면 해당 설치로 전달하고 동일 설치의 작업들은 작업 ID로 구분한다. 작업 화면은 서버 측에서 인가된 작업과 Run만 읽는다. 기존 전체 대시보드의 비로그인 로컬 권한을 공유 서버의 신뢰 경계로 사용하지 않는다. 브라우저에 전체 Host 제어 자격을 주지 않는다. 열기 권한은 대상에 한정하고 만료·재사용·로그 유출을 방지한다. 회사 wrapper는 영속 작업 핸들과 현재 창 컨텍스트를 전달한다.

## 순서와 검증

1. Windows executions.db 확장, 자격 관리·공유 정책·소유권 및 이전, v1 회귀. 임시 프로필/DB로 테스트한다.
2. 복사형 plugin.py 작업 등록·복구·실행·열기, 계정별 파일과 작업별 설정, 재접수 보존.
3. Windows Manager 웹·Qt와 Linux 모니터의 작업 목록/선택/오프라인/인가된 고정 화면. 모니터 없이도 기존 Run은 계속한다.
4. 단일 스크립트로 동일 계정 두 작업, 다른 계정, 경쟁, 권한·조회범위, 구버전, 장애·재시작·인계, UI, 회사 복사형 패키지 검증을 실행한다. 원본 및 재시도 로그는 .local-reports 에 둔다. 실사용 Windows SSH·회사 계정·장비는 별도 인수다.

코드 접점은 execution/host.py 및 connector_runs.py, standalone/direct_connector_client.py 및 plugin_commands.py, apps/agent-monitor/plugin.py, connector/supervisor.py 및 웹·Qt, backend/api/main.py와 작업 화면이다. DB 이전은 추가형이며 원본 복구는 유휴 상태에서 이전 바이너리와 전환 전 DB 백업을 함께 사용한다. 회사 적용 전 고정 소스와 패키지 해시, 구버전 보관 경로를 PORT-021에 기록한다.

## 독립 리뷰 반영과 인터페이스

- Host의 기존 UNIQUE 멱등키는 공유 작업 식별자와 원 요청 키에서 만든 내부 키로 범위를 제한한다. 기존 tombstone과 충돌 응답, active/history에도 동일한 인가 및 필드 제한을 적용한다.
- 운영자 승인 표에 monitor_id, 계정, SSH 프로필, remote port를 고정한다. 열 때 해당 transport generation에서 목적지 인스턴스를 확인한다. 여러 목적지를 열 수 있어야 하고 재연결 전 세대의 포트/URL을 재사용하지 않는다.
- 공유 Monitor 리스너는 기본 거부다. health, 작업 전용 뷰 및 그 인증 경로만 공개하며 기존 대시보드와 alias/API는 작업 브라우저에 열지 않는다. 탭별 단기 자격은 다른 작업으로 전이되지 않는다. 인계와 폐기 시 새로 조회할 때 현재 owner와 epoch를 검사한다.
- 인계는 Run 단위 CAS다. 이전 분석 lease·지연 명령·재접수의 권한을 회수한다. 기존 실행 자체는 유지한다. 개별 작업의 다른 Run은 인계하지 않는다.
- legacy 회사 서비스가 필요한 경우 운영자가 별도 service principal을 발급하고 batch/prepare/poll/release 등 서비스 전용 경로만 허용한다. 직결 Host의 장비 배타 검사는 두 진입 경로 모두 유지한다.
- T-324에 cross-task 동일 멱등키·tombstone·history, 다른 설치 포트·재연결, 두 탭·쿠키 없는 기본 API, 기존 서비스 플로우와 장비 경합, 인계와 지연 분석 결정을 포함한다.

### 원본 구현 접점

Host 공통 경로는 /v1/sharing 아래에 둔다. Authorization Bearer는 계정 또는 운영자/서비스 자격, X-Bsp-Task-Key는 작업 자격이다. 클라이언트가 생성해 보관한 작업 ID와 작업 자격으로 PUT /v1/sharing/tasks/{task_id}에 project, monitor_id를 전달한다(동일 자격 재시도 허용). Host는 GET /v1/sharing/tasks에서 인증된 범위의 tasks, active_task_id를 반환한다. 작업 항목은 task_id, account, project, monitor_id, last_seen_at, active_run_id를 가진다. Windows Manager는 로컬 운영자 자격으로 호출한다. 설치별 모니터 포트는 Windows 관리자 설정에 둔다. 실제 인증·프로비저닝과 작업 화면 발급의 세부 입력은 구현 단위 간 동기화한다.

## 연결 대상 확인

공유 Linux에서 계정/서비스 자격을 전송하기 전 운영자 소유 Unix 소켓 또는 운영자가 바인딩 권한을 보장하는 루프백 경로를 명시한다. Windows는 승인 Monitor의 등록 키로 생성한 새 응답을 확인한 뒤 일회용 열기 권한을 발급한다. 대상 설치도 키를 증명해야 권한을 교환할 수 있고, 브라우저에는 해당 설치의 탭에서만 유효한 조회 자격을 제공한다. 상세 프로비저닝은 [PORT-021](../porting/PORT-021.md)을 참조한다.
