## DEV-PORT-01 · 2026-11-03 회사판 이식 절차

사용자 확정: 이 저장소에서 구현·검증한 코드와 시험을 재사용해 별도로 확장된 회사 대시보드에 이식한다. 회사 담당 Claude/OpenCode는 회사 추가 기능을 보존하며 다른 연결 부분을 조정한다. 원본은 기능별 고정 커밋·선행 조건·변경 접점·검증 근거를 전달하고, 회사는 구조 차이와 기능별 적용·검증 이력을 회사 저장소에 유지한다. 사용자는 이 절차의 문서 갱신·커밋·푸시를 요청했다.

구현 선택: [이식 절차](../porting/README.md), PORT 안내서 양식, COMPANY_MAP/APPLIED 회사 전용 기록 양식을 제공한다. 원본 일반 개발과 회사 이식의 읽기 순서를 구분하되 필수 정책·관련 계약·회귀 시험은 유지한다. 개발 전달 절차 변경이므로 제품 RQ/T 번호를 새로 부여하지 않으며 `DOC-PORT-01~03` 문서 검사로 확인한다. 제품 동작·DB·운영 권한 변경, 기존 기능 전체의 이식 묶음 발행, 실제 회사 적용은 이번 범위가 아니다. [검증 기록](../testing/runs/20261103-porting-workflow.md).

## D-45 · 2026-11-01 TC 작업 화면 후속 변경

사용자 명시 요청으로 RQ-39 범위를 확장한다. 경로 트리/검색/표시 정렬, 목록 내 드래그(번호 제거), 설정 접기, 검색 패널 숨김·너비 저장을 채택했다. 표시 정렬은 실행 순서를 변경하지 않으며 폴더를 넘는 정확한 실행 순서는 번호 없는 펼침 목록에서 확인한다.

실패 TC 재실행은 원본 소스·보드 snapshot과 parent_run_id를 사용하는 단일 TC 새 Run이다. 원본 Run 종료/제어권/Preflight/예약 조건을 유지하며 선행 TC가 필수인 경우 서버 검증을 우회하지 않는다. 부분 재실행은 Dashboard 전체 판정을 갱신하지 않는다.

사용량은 어댑터의 구조화된 누적 snapshot만 저장한다. 모델/provider별 입력·출력 토큰, 보고된 USD 비용을 합산하고 미수집 비용은 추정하지 않는다. Mock는 모델 호출이 없다. 실제 모델 어댑터 계량 연동은 후속 인수 범위다. DB 테이블 변경 없이 기존 Attempt JSON에 optional usage/usage_sequence를 추가한다.

## D-46 · 2026-11-01 반복 실행·설정 탭·작은 탐색기형 목록

사용자 후속 요청에 따라 설정을 톱니바퀴 탭으로 통합한다. 소스/Suite도 설정에 포함한다. 기본은 실행 및 결과이며 Preflight/시작은 결과 화면에 둔다. 탭 내용은 unmount하지 않아 입력을 유지한다. 돌아가기 버튼/톱니바퀴 재클릭/Esc가 결과 탭으로 복귀하며 포커스를 돌려준다.

TC 행은 기본 32px/12px 한 줄이다. 반복 아이콘을 클릭할 때만 횟수 편집을 펼친다. 1회는 숫자를 생략하고 변경된 횟수만 ×N으로 표시한다. 목록 정렬 드롭다운을 제거하고 이름·유형·시간 제목 클릭으로 방향을 바꾼다. 표시 정렬과 선택 실행 순서는 별개다.

RQ-40 구현 선택: TC별 1~100회, 전체 1~100회, 조합 최대 10,000회. 전체 회차마다 선택 순서대로 각 TC를 지정 횟수 연속 실행한다. 시작 시 (TC/전체 회차/TC 회차) plan을 고정한다. 각 slot의 마지막 Attempt 판정이 진행률에 반영되며 오류 복구는 같은 slot을 재시도한다. 서로 다른 slot의 FAIL은 성공으로 지우지 않는다. 모든 slot 종료 전 취소는 INCOMPLETE다. 사용량은 실제 모든 Attempt 합산이며 중복 snapshot은 제외한다.

기존 Run은 plan이 없으면 1회 실행으로 처리한다. SQLite 테이블 이전 없이 Run/Suite/Attempt JSON optional 필드를 추가한다. 단일 FAIL Retry는 별도 1회 Run이고 전체 재검증은 원본 반복 계획을 복제한다. 실제 장비·모델 인수는 별도다.

D-46 후속(RQ-41): 실행 대상은 runner가 `report_target`/최종 result로 보고하는 local 또는 Single/Dual 보드 snapshot이다. UI 요청으로 실제 대상 정보를 만들지 않는다. 보드 ID/host/COM이 pin과 일치하고 이름이 있는 보고만 기록하며 Attempt 내 대상을 덮어쓰지 않는다. 현재 Mock는 local이다. 실제 BCM adapter 미연동/과거 대상 미기록은 명확히 구분한다.

## D-47 · 2026-11-03 빌드·전체 선택·Windows TC 실행 연결

## D-53 · 2026-11-04 Windows Runner 포터블 실행파일

사용자가 회사 노트북의 Runner 의존성 설치 실패를 줄이기 위해 여기서 실행파일을 빌드하여 전달하는 방식을 승인했다. Windows x64용 Python 런타임·Runner 의존성을 포함하는 폴더형 ZIP과 콘솔 EXE를 제공한다. 최초 연결 설정 후 저장한 설정으로 Runner와 SSH 터널을 함께 시작한다. 패키징 도구·버전·내부 실행 방식은 구현 선택이며 검증 기록에 남긴다.

기존 사용자 홈의 설정·DPAPI 토큰·runtime·DB와 실행 불명 기록을 유지한다. Runner용 pip 설치를 생략하되 TC는 기존 외부 Python을 명시적으로 지정한다. 실행파일을 TC Python 기본값으로 저장하지 않는다. 외부 Python 환경과 프로세스 격리, 토큰 비전달, loopback 인증, 정상 종료 및 중복 방지 계약을 보존한다. 회사 OpenSSH·드라이버·fastboot·TC 패키지는 별도다. 실제 회사 환경과 보드 인수는 T-160 및 기존 T-130/136/141로 남긴다.
