# 결정 기록

기존 D 번호는 [종합 계획 §10](../BSP_OS_UPGRADE_DASHBOARD_PLAN.md)에 보존한다. 아래 ADR은 구현 구체화안이며 사용자 확정으로 표현하지 않는다.

## 확정 운영 정책 묶음

| 결정 | 요약 |
|---|---|
| D-01, D-11, D-27 | 전체 분석 후 최초 계획 확인, 작업별 Claude 조정 세션, 영속 모듈 목록 |
| D-03, D-20, D-21 | 새 판단만 Jira·의존 작업 대기, 실패 단계 재시도, 분석은 선행 게이트 예외 |
| D-14, D-15 | 분석 병렬, 수정·빌드 순차, 미래 격리 병렬 고려 |
| D-22, D-24, D-25 | 종합 진행도 5개 집계, 모듈 비교형 접이식 표 |
| D-23, D-28, D-34 | 두 실행 모드, 초기 수동 장비 시험, 유효한 필수 결과면 추가 승인 없이 시험 완료 |
| D-30, D-31, D-33 | OpenCode 기본·동일 원인 수정 2회 실패/난항 시 Opus, 작성자별 리뷰, 도구 미설치 시 Claude 대체 |
| D-35 | 사내 Jira 직접 설정 또는 실제 Claude MCP 연결 선택 |
| D-39 | 작업별 Claude 오케스트레이터가 계획·해석·다음 행동 제안. 실제 실행/상태는 기존 서버 소유. 관련 전체 문서와 역할별 보고 규칙 갱신 |

## 구현 상세 결정 제안

| ID | 상태 | 제안·채택 시 검증할 것 |
|---|---|---|
| ADR-01 | ACCEPTED_LOCAL | React/TypeScript + Python/FastAPI + Linux 로컬 SQLite WAL. 단일 관리자, SSH 터널, worker 분리. 실제 환경·버전·배포 방식 확인 후 채택 |
| ADR-02 | PROPOSED | 필수 leaf unit 동일 가중치, 구현=설계+코드, 과거 무효 결과 제외. 필수 사례 목록 확정 및 집계 fixture 검증 |
| ADR-03 | PROPOSED | command idempotency, optimistic version, lease+token+실행 확인, outbox. crash 구간별 중복 방지 시험 필요 |
| ADR-04 | PROPOSED | 혼합 작성에 Claude 코드가 있으면 Codex 리뷰 경로. 리뷰 이후 변경은 재리뷰 |
| ADR-05 | PROPOSED | 승인 후 범위·그룹·필수 시험 변경은 새 plan_version. 사용자 판단이 바뀌는 변경만 재확인, 단순 표시/내부 세분화는 근거 기록 |
| ADR-06 | DESIGNED_NOT_IMPLEMENTED | 이벤트 기반 조정 호출, 영속 제안·명령 중복 방지, 보고 v2·판단 후보/범위 보류, 계약 버전 협의, 한도/복구. 상세 필드와 기본 한도는 구현 기준안이며 실제 인수 전 |

채택 기록에는 날짜, 담당, 이유, 대안, 영향 문서/시험, 근거를 추가한다. routine 기술 결정은 환경 확인 후 작업자가 채택할 수 있다. 사용자의 범위·운영 정책 변경은 사용자 판단을 받는다.

## 미결정/실제 확인 필요

- D-02/10/12/17: 실제 대상·호스트·계정·폴더·선행 그룹·빌드 명령.
- D-07/29/32: 실제 CLI 호출/재개/병렬 분석 수, 세션 유실 복구, 일반 리뷰 모델, Opus 이후 한도. 지원되지 않는 기능을 있는 것처럼 구현하지 않는다.
- D-08/19: 보드·이미지·필수 시험·예외와 최종 회귀 범위.
- D-04/09: Jira 배포/API·인증·필드·MCP 기능·중복 검색 지원.
- D-13/18: 자동 보드팜/Windows 테스트 연동은 후속 범위다.

구현 중 새 항목은 `OPEN → PROPOSED → ACCEPTED/SUPERSEDED`로 관리한다. 기존 결정은 삭제하지 않고 대체 ID를 연결한다.

## 2026-10-12 채택·변경 기록

- ADR-01: Codex가 React/TypeScript, FastAPI, SQLite WAL, 별도 worker를 로컬 구현에 채택. Linux는 실행 대상이고 현재 검증 환경은 macOS. 실제 Linux/SSH/서비스 운영 검증은 미실행.
- D-36 (사용자 확정): 수동시험은 PASS/FAIL만 필수 입력. 기타 메타데이터·로그는 선택. 현재 작업/이미지/소스/시험 계획과 등록 시각은 서버 자동 연결. 이전 D-28의 근거·보드 필수 입력 부분을 대체. RQ-14/15, T-61~63에 반영.
- D-37 (사용자 확정): 데모의 선행 모듈 수동 완료 지원. 실제 실행과 후속 그룹에는 불가. 최초 계획/관련 판단/일시 중지/최종 검토 유지. RQ-28, T-64~67에 반영.
- 이번 코드와 README/관련 설계/검증 기록의 GitHub 병합은 사용자 지시로 수행한다. 실제 OS 변경이나 Jira 티켓 발송 승인은 포함하지 않는다.

- D-38 (2026-10-12 사용자 확정): 단일 운영자 로컬/SSH 터널 대시보드의 접속 키·로그인 단계를 제거한다. access-token 파일과 세션 쿠키를 사용하지 않고 화면을 바로 연다. OS 업그레이드 시작/계획 확인은 기존 흐름을 유지한다. SSH·Jira·에이전트 인증은 별개다. RQ-29, T-68~70에 반영.

- D-39 (2026-10-12 사용자 확정 방향): 작업별 오케스트레이터를 두고 역할과 각 agent의 보고 방식을 명확히 문서화하며 영향받는 전체 문서를 갱신한다. 기존 Claude 조정 세션을 확장해 계획·결과 해석·실패 대응·판단 제안을 맡기고, 실행 관리자에게 게이트·배정·DB 상태/집계 권한을 유지한다. 이번 요청의 작업 범위는 문서 작성·정합성 확인이다.
- ADR-06: 위 방향의 구체화는 [오케스트레이터 명세](../design/ORCHESTRATOR_SPEC.md)와 [모듈 보고 계약](../design/AGENT_STATUS_CONTRACT.md) v2 설계에 기록했다. 상태/필드·이전 방식·120초/20회 등의 기본값은 사용자 개별 확정값이 아닌 구현 기준안이다. 새 조정 호출, v2, 후보 자동 접수는 미구현. RQ-30~34, T-71~85에 연결한다.

- D-40 (2026-10-12 사용자 요청): 문서 작성 후 Claude에서 쓸 오케스트레이터 agent를 만들고 가능한 시험과 기록 갱신을 수행한다. 실제 Claude 동작은 사용자가 직접 실행한다.
- ADR-07: 이번 납품은 기존 권한 경계를 유지한 수동 호출 패키지 M0이다. 프로젝트 로컬 agent, Read/Glob/Grep, model inherit, Python 표준 라이브러리 검사/내보내기, 실행 없는 claude-manual-v1 프로필을 채택한다. 이 구체적인 패키지 방식은 구현 선택이며 별도 사용자 확정 정책으로 표시하지 않는다. 자동 대시보드 O1~O5/모듈 v2는 후속 범위다.

- D-41 (2026-10-12 사용자 요청): 고정 소스 커밋/해시의 필요성을 검토하고 에이전트·빌드 브리지의 사용법 및 기본값을 제공한다.
- ADR-08: 입력 편의를 위해 소스 기준 기본값을 빈칸(새 작업 시 깨끗한 new_base Git HEAD 자동 기록)으로 변경한다. 직접 40/64자리 해시 지정과 데모 기준을 유지한다. 브리지 기본 위치는 workspace/.bsp-dashboard/bridges이며 파일·권한 점검과 빈 항목 채우기를 제공한다. 실제 도구 전용 wrapper는 환경별 연결 대상이고 기본값만으로 연결 성공을 표시하지 않는다. 이는 D-41에 대한 구현 선택이다.


- D-42 (2026-10-12 사용자 확정): 작업 폴더에서 설치된 Claude/OpenCode/Codex를 대시보드가 자동 연결한다. 사용자가 bridges 폴더/연결 스크립트를 만들지 않도록 코드·설정 화면·전체 문서를 갱신한다. Linux 실행 관리자와 Windows 브라우저 구성, 기존 게이트·교차 리뷰·사람 시험을 유지한다.
- ADR-09 (ACCEPTED_LOCAL): runner=native를 기본으로 하고 기존 JSON 브리지는 고급 호환 경로로 보존한다. CLI별 비대화형 결과 정규화, PATH/명시 경로 탐지·옵션/로컬 로그인 점검, 역할 지침 snapshot, 등록된 Bash 빌드/검증/통합 명령과 산출물 검증을 채택한다. DB 테이블 변경 없음. ADR-08의 브리지 기본 경로는 고급 모드로 한정하며 소스 자동 기준은 유지한다. 실제 CLI/BSP 인수는 별도 T-102로 추적한다.

- D-43 (2026-10-25 사용자 확정): 첨부 GUI Test 요구사항/통합/모듈 계획을 기준으로 별도 feature 브랜치와 PR에서 구현한다. 기존 Dashboard 보존, gui_test/ 분리, Windows 단독/통합 모드, 기존 COM CLI 인자 전달, 실제 TC/RBM은 Mock, E2E/회귀/설치 문서, 공개 저장소의 사내 정보 제외.
- ADR-10 (ACCEPTED_LOCAL): 모드별 별도 SQLite DB, 기존 Dashboard Worker에 독립 GUI Worker tick 추가, 공통 React 화면을 두 Vite 빌드로 재사용, Mock Dashboard DB 분리, 자동 결과 내부 명령 및 멱등 outbox, 서버 측 기준 재검증. 기존 DB schema_version=1은 변경하지 않는다. 실장비/사내 API를 설정 없이 활성화하는 경로는 없다.

- D-44 (2026-10-25 사용자 요청): GUI Test 설정과 Test cases의 Git 브랜치 등을 접고 펼치도록 하고, TC 목록을 정돈하며, 실행 순서는 TC를 끌어 위아래로 바꾸도록 한다. 후속 요구사항도 관련 문서에 함께 갱신한다. RQ-39, T-109~111에 연결한다. 실행 모드·게이트·외부 연동 정책 변경은 없다.
- ADR-11 (ACCEPTED_LOCAL): 공통 React 화면에서 설정 영역별 접힘 상태를 브라우저 localStorage에 기억하고, 숨긴 입력은 유지한다. 소스 설정은 최초 접힘, 그 외 설정은 최초 펼침이다. TC 폴더 선택과 폴더 펼침을 분리하고 부분 선택/Single·Dual/개수를 표시한다. 실행 순서의 드래그와 번호 선택을 함께 제공한다. 이는 구현 선택이며 DB·API·운영 권한 변경은 없다.
