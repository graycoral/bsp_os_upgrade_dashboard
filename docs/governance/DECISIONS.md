# 결정 기록

## D-59 후속 · 2026-11-06 Test 설정 간소화

사용자는 Test 설정을 여러 큰 패널로 나누지 않고 하나로 묶어 콤보박스와 기본값으로 입력 부담을 줄이며, Test 현황 안의 설정도 동일하게 변경하도록 확정했다. RQ-55의 단일 공유 편집기를 유지하고 하나의 `Test 설정` 접기 안에 카테고리 선택을 둔다. 내부 편집기는 unmount하지 않고 숨기며, 전체 접기는 바깥 Test 설정에만 적용한다. 등록 보드와 반복 선택이 기본 화면이며 수동 입력·명령 편집·조회 고급 설정·긴 소스 정보는 필요할 때 펼친다. 저장된 값과 미저장 입력을 덮어쓰지 않으며 legacy 소스도 현재 적용 상태를 초기 선택으로 사용한다. 오류는 해당 카테고리와 필요한 상세를 열어 확인할 수 있게 한다. 자동 저장·소스 확인/적용·외부 실행을 추가하는 결정은 아니다.

## D-60 · 2026-11-06 TC 소스 위치·Git 브랜치·관리 스냅샷

사용자는 GUI Test 소스를 단순한 데모 브랜치 목록에서 고르는 대신 Linux 파일 경로 또는 Gerrit/GitHub URL로 입력하고 해당 원본의 브랜치를 선택하도록 요청했다. RQ-56/T-176~182로 추적하며 RQ-52의 읽기 전용 Git 표시와 별개의 명시적 소스 준비·적용 기능이다. 전체 설정/관련 탭의 공유 편집과 접기 RQ-55/D-59를 유지한다.

구현 선택: 서버 폴더 또는 Git clone URL 입력 → 소스 확인 → 발견된 ref 선택 → 소스 적용의 네 단계를 사용한다. GET `/source`, POST `/source/inspect`, PUT `/source`를 normal/live GUI prefix에 제공하고 설정 버전과 확인 ID로 오래된 적용을 거부한다. 관리 스냅샷은 Git 커밋 트리 또는 비 Git 폴더 현재 파일을 고정하며 실제 실행에 같은 소스 기준을 전달한다. Git 폴더의 미커밋 파일과 원본 checkout은 포함하지 않는다. 서버의 기존 인증 환경을 사용하고 비밀 URL은 받지 않는다. 세부 API/저장/Runner 계약은 [GUI Test 계약](../design/GUI_TEST_CONTRACT.md)에 단독 정의한다.

원래 legacy 소스는 기본값으로 유지하고 default/live 저장소는 분리한다. Runner 연결과 무관하게 소스 확인·적용·카탈로그 조회는 제공하며 관리 스냅샷 미지원 Runner에는 실행 차단과 업데이트 이유를 표시한다. 소스 전달 가능은 보드 준비나 시험 PASS를 뜻하지 않는다. 적용 시 선택·반복·Suite·Preflight를 초기화하고 미저장 명령과 과거 Run은 보존한다. 소스 변경이 Mock/실제 보기 모드를 바꾸지 않는다. 개발 중 외부 원격 Git·실장비 실행은 포함하지 않으며 [실행·독립 검토 기록](../testing/runs/20261106-settings-sync.md)에 실제 증거와 미수행을 구분한다.

## D-59 · 2026-11-06 전체 환경 설정과 문맥별 편집 공유

사용자는 환경 설정에 모든 기존 설정을 모으고 그룹별/전체 접기를 제공하며 각 관련 탭에서도 자기 설정을 편집하고 양방향으로 동기화하도록 지시했다. 통합 Test 현황의 보기 모드를 환경 설정에서만 편집하도록 했던 이전 배치는 이번 최신 지시로 대체한다. 명시적 적용/재로드와 URL 우선순위는 유지한다. RQ-55/T-169~175에 연결한다.

구현 선택: BSP 폼 하나를 고정 위치에 유지하고 표시 그룹만 변경한다. 대시보드는 실행 환경·에이전트/빌드·구조화 보고/조정·모듈, 사람 검토/Jira는 Jira를 문맥별 접기 안에서 제공한다. GUI Test는 첫 진입 이후 한 컴포넌트를 유지하여 전체 설정과 Test 현황에서 같은 설정 입력·명령 편집기·보기 모드 선택을 사용한다. TC 목록·선택·순서·개별 반복·실행·결과는 Test 현황에만 표시한다. 포털이나 복제 폼·별도 draft 저장소는 만들지 않는다. 접기는 내용을 숨기며 unmount하지 않는다.

사용자 후속 정정: 환경 설정에는 Test 현황의 설정 항목만 모으며 Test 작업 화면 전체를 옮기지 않는다. 최초 구현에서 TC 목록까지 전역에 표시한 것은 구현자의 잘못된 해석이며 사용자 확정 요구가 아니었다. 전역에서는 설정만 단일 열로 표시하고 같은 입력 상태의 양방향 공유와 접기/펼치기는 유지한다. 초기 배치 이력은 [기존 기록](../testing/runs/20261106-settings-sync.md)에 보존하고 수정·검증은 [설정 전용 표시 기록](../testing/runs/20261106-settings-only.md)에 남긴다.

전역 접기는 BSP와 GUI 그룹 모두에 전달하며 개별 펼침 상태는 브라우저에 저장한다. Test 현황/전체 설정에서만 GUI 초기 조회·모듈 선택 조회·Run 폴링을 활성화하고 다른 탭에서는 취소한다. BSP 저장은 전체 BSP 프로필에만 적용하며 GUI 저장·브라우저 모드 적용과 구분한다. 기존 job snapshot·Run 기록·운영 게이트·API·DB·수동 기본값을 보존하고 실제 모델·SSH·장비·Jira 실행을 포함하지 않는다. [화면 명세](../design/UI_SPEC.md), [실행·검토 기록](../testing/runs/20261106-settings-sync.md)을 따른다. 시험이나 독립 리뷰 완료 여부는 해당 증거가 있을 때만 기록한다.

## D-58 · 2026-11-06 자동 조정 O1~O4·모듈 v2·복구 구현

사용자가 남은 O1~O4와 복구 검증의 구현을 승인했다. 2026-10-12 D-39의 문서 전용 범위를 소급 변경하지 않고 이번 구현 승인을 별도로 기록한다. RQ-30~34/T-71~85에 연결한다. 실제 모델/BSP/장비/Jira 운영 실행은 이번 로컬 구현·모의 검증의 승인에 포함하지 않는다.

구현 선택: 기본 `module_report_version=1`, `orchestration.enabled=false`, 새 job 생성 때 capability/프로필 고정, BSP DB의 추가 schema1→2 이전, 별도 조정 큐와 기존 worker의 유일한 모듈 배정 권한, 구조화 명령 결과·실제 소스/diff/근거 검사다. 조정 기본120초/20회/오래된 기준 재계획2회/자동 재시도0회는 구현 선택이며 사용자 개별 확정 숫자로 격상하지 않는다. 기본 수동 장비 시험·최종 사람 검토·v1/과거 job·수동 Claude 패키지는 유지한다. [현재 설정/복구 안내](../agents/ORCHESTRATION_V2_OPERATIONS.md), [진행 중 실행/독립 리뷰](../testing/runs/20261106-orchestration-v2.md)를 따른다. 운영 baseline NONE이다.

## DEV-PORT-01 · 2026-11-03 회사판 이식 절차

[검증 기록](../testing/runs/20261103-porting-workflow.md).

## 2026-10-12 채택·변경 기록

- ADR-01: Codex가 React/TypeScript, FastAPI, SQLite WAL, 별도 worker를 로컬 구현에 채택. Linux는 실행 대상이고 현재 검증 환경은 macOS. 실제 Linux/SSH/서비스 운영 검증은 미실행.
- D-36 (사용자 확정): 수동시험은 PASS/FAIL만 필수 입력. 기타 메타데이터·로그는 선택. 현재 작업/이미지/소스/시험 계획과 등록 시각은 서버 자동 연결. 이전 D-28의 근거·보드 필수 입력 부분을 대체. RQ-14/15, T-61~63에 반영.
- D-37 (사용자 확정): 데모의 선행 모듈 수동 완료 지원. 실제 실행과 후속 그룹에는 불가. 최초 계획/관련 판단/일시 중지/최종 검토 유지. RQ-28, T-64~67에 반영.

## D-45 · 2026-11-01 TC 작업 화면 후속 변경

사용자 명시 요청으로 RQ-39 범위를 확장한다. 경로 트리/검색/표시 정렬, 목록 내 드래그(번호 제거), 설정 접기, 검색 패널 숨김·너비 저장을 채택했다. 표시 정렬은 실행 순서를 변경하지 않으며 폴더를 넘는 정확한 실행 순서는 번호 없는 펼침 목록에서 확인한다.

실패 TC 재실행은 원본 소스·보드 snapshot과 parent_run_id를 사용하는 단일 TC 새 Run이다. 원본 Run 종료/제어권/Preflight/예약 조건을 유지하며 선행 TC가 필수인 경우 서버 검증을 우회하지 않는다. 부분 재실행은 Dashboard 전체 판정을 갱신하지 않는다.

사용량은 어댑터의 구조화된 누적 snapshot만 저장한다. 모델/provider별 입력·출력 토큰, 보고된 USD 비용을 합산하고 미수집 비용은 추정하지 않는다. Mock는 모델 호출이 없다. 실제 모델 어댑터 계량 연동은 후속 인수 범위다. DB 테이블 변경 없이 기존 Attempt JSON에 optional usage/usage_sequence를 추가한다.

## D-46 · 2026-11-01 반복 실행·설정 탭·작은 탐색기형 목록

사용자 후속 요청에 따라 설정을 톱니바퀴 탭으로 통합한다. 소스/Suite도 설정에 포함한다. 기본은 실행 및 결과이며 Preflight/시작은 결과 화면에 둔다. 탭 내용은 unmount하지 않아 입력을 유지한다. 돌아가기 버튼/톱니바퀴 재클릭/Esc가 결과 탭으로 복귀하며 포커스를 돌려준다.

TC 행은 기본 32px/12px 한 줄이다. 반복 아이콘을 클릭할 때만 횟수 편집을 펼친다. 1회는 숫자를 생략하고 변경된 횟수만 ×N으로 표시한다. 목록 정렬 드롭다운을 제거하고 이름·유형·시간 제목 클릭으로 방향을 바꾼다. 표시 정렬과 선택 실행 순서는 별개다.

RQ-40 구현 선택: TC별 1~100회, 전체 1~100회, 조합 최대 10,000회. 전체 회차마다 선택 순서대로 각 TC를 지정 횟수 연속 실행한다. 시작 시 (TC/전체 회차/TC 회차) plan을 고정한다. 각 slot의 마지막 Attempt 판정이 진행률에 반영되며 오류 복구는 같은 slot을 재시도한다. 서로 다른 slot의 FAIL은 성공으로 지우지 않는다. 모든 slot 종료 전 취소는 INCOMPLETE다. 사용량은 실제 모든 Attempt 합산이며 중복 snapshot은 제외한다.

기존 Run은 plan이 없으면 1회 실행으로 처리한다. SQLite 테이블 이전 없이 Run/Suite/Attempt JSON optional 필드를 추가한다. 단일 FAIL Retry는 별도 1회 Run이고 전체 재검증은 원본 반복 계획을 복제한다. 실제 장비·모델 인수는 별도다.

D-46 후속(RQ-41): 실행 대상은 runner가 `report_target`/최종 result로 보고하는 local 또는 Single/Dual 보드 snapshot이다. UI 요청으로 실제 대상 정보를 만들지 않는다. 보드 ID/host/COM이 pin과 일치하고 이름이 있는 보고만 기록하며 Attempt 내 대상을 덮어쓰지 않는다. 현재 Mock는 local이다. 실제 BCM adapter 미연동/과거 대상 미기록은 명확히 구분한다.

## D-47 · 2026-11-03 빌드·전체 선택·Windows TC 실행 연결

사용자 요청: `scripts`에 빌드 스크립트, TC 전체 선택 체크박스를 추가한다. Mock를 넘어 **이 저장소**의 Dashboard에서 사용하려 한다. 현재 서버/TC 경로/명령 예시는 준비되지 않았다. 사용자가 실제 Linux 실행을 맡으며 Codex는 코드와 시험을 진행한다.

사용자 확인 사실: 이전에는 Windows 탐색기에서 Linux 테스트 공유 경로를 열고 그곳의 Python 스크립트를 실행했다. 파일 저장 위치는 Linux, 실행 위치는 Windows이며 로컬 COM을 사용한다. 이를 Linux Python 실행 또는 RBC 원격 직렬 연결로 추정하지 않는다.

구현 선택(사용자가 통신 프로토콜을 지정한 것은 아님): Windows loopback 실행기 + SSH 역방향 포워딩으로 Linux Dashboard와 연결한다. 고정 Windows Python/TC 경로와 등록 보드·COM을 사용하고 source snapshot·실행 요청 ID·로그/종료 근거를 보존한다. 별도 JSON 설정으로 활성화하며 기본 Mock와 DB를 분리한다. 보드 이미지·매핑 증거가 없으므로 실제 Job 자동 완료는 계속 차단한다. 자세한 현재 계약은 [GUI Test 계약](../design/GUI_TEST_CONTRACT.md), 설정은 [실행기 안내](../gui_test/WINDOWS_RUNNER.md).

검토 방식 사용자 확정: 새로운 Astra 세션에서 구현 리뷰, 또 다른 GPT-6-sol 세션에서 테스트만 수행. 주 Codex가 결과를 검토해 수정하고 재시험을 지시한다. 실제 리뷰/시험 결과와 코드 기준은 실행 기록에 남긴다. 이를 Claude 검토 또는 실장비 인수 완료로 표현하지 않는다.

D-47 화면 후속(2026-11-03 사용자 요청): 연결 유형 선택을 작고 간결하게 표시하고 전체 선택 체크박스를 이름 제목 옆으로 이동한다. 구현 선택은 검색과 유형 필터를 같은 줄에 배치하고 전체 선택과 이름 정렬을 별도 제어로 유지하는 것이다. RQ-39/T-125, API·저장 데이터·실행 정책 변경 없음.

D-47 화면 추가 확인(2026-11-03 사용자): 전체 선택은 이름과 같은 행의 바로 왼쪽을 의미한다. TC 순서 변경은 드래그만으로 충분하므로 위아래 이동 버튼과 관련 로직/스타일을 제거한다. 기존 문서의 위아래 버튼 키보드 대안은 이 사용자 요청으로 대체한다. 실행 명령은 사용자가 별도로 제공할 예정이며 수신 전 추정하여 연결하지 않는다.

D-47 실행 명령 확인: 사용자 Single 예는 `python3 tc1.py -p COM7`이다. Windows UI 신규 프로파일의 Single 기본값을 이 형식으로 제공하고 python3/python을 모두 설정된 고정 Python 실행 파일로 치환한다(구현 선택). 저장 프로파일·Mock 기본값은 보존한다. Dual은 `-n/-n2` 노드명을 사용하며 사용자가 노드명을 확인 중이므로 COM 값으로 대신 구현하지 않는다.

D-47 후속 확정: 사용자가 Dual 실제 예 `python3 tc_2.py -n n295_sadk -n2 n296_sadk`를 제공하여 위 노드명 확인 대기를 해소했다. 선택 보드에 별도 node 값을 등록하고 {node_a}/{node_b}로 전달한다. 기존 COM 쌍 프로파일은 보존하고 노드/COM placeholder 혼합은 거부한다. COM8은 예제 두 번째 포트일 뿐 사용자 확정 장비 번호가 아니다. 실제 장비 검증은 여전히 미수행이다.

D-47 비용 화면 후속(사용자 요청): 토큰·비용 상세를 기본 접힘으로 두고 진행률 아래 완료 수·간략 비용을 표시한다. 구현 선택은 Run/TC별 native details와 반복 포함 PASS/FAIL 완료 횟수, 모델 보고 비용 합계다. 일부/미집계를0으로 바꾸거나 가격을 추정하지 않는다.

D-47 화면 후속(2026-11-03): 사용자가 실행/결과 분리·결과 상단·세션 ID의 설정 아이콘 왼쪽 배치·나머지 내용의 접기/펼치기를 요청했다. 구현 선택은 같은 화면에 결과 카드/실행 카드를 위아래 배치하고 기존 Run 선택을 상단으로 옮기는 것이다. 브라우저 내부 제어 세션 값 대신 사용자 실행 이력 Run ID를 표시한다. 접힘은 표시 상태만 바꾸며 실행/권한/Preflight 게이트를 유지한다.

## D-48 · 2026-11-03 자동 이미지 퓨징과 TC 연결

사용자 확인: Linux 공유 이미지 폴더의 배치를 Windows에서 더블클릭하여 퓨징했고 완료 시 보드가 재부팅한다. 콘솔 reboot lkshell 후 lkshell에서 fast를 입력하면 fastboot로 진입한다. 사용자는 검증 완료 후 테스트 단계에서 이미지 퓨징과 TC가 자동으로 이어져야 한다고 요구했고 구현·요구사항 갱신을 승인했다. 실제 보드 실행은 별도다.

## D-66 · 2026-11-12 Windows Runner 설정 편의

사용자는 개행의 권장값 사용, 현재 명령 `reboot lkshell`, fastboot 경로·serial 자동 조회, 보드마다 반복하지 않는 공통 설정과 대시보드 재빌드 후 Runner 재설치 부담 개선을 요청했다. RQ-62는 설정 마법사 범위에서 구현한다. 기술 선택은 기존값 우선·새 입력의 115200/`cr` 권장, PATH/표준 SDK 탐색, 읽기 전용 `fastboot devices`, 단일 보드/단일 장치 자동 선택이다. 다중 보드 COM↔USB 대응과 기존 serial 변경은 사용자 선택을 유지한다. 준비 프롬프트·정상 부팅 문구는 실제 출력이 필요하며 명령어로 대체하지 않는다.

공통 입력은 기존 보드별 설정으로 펼쳐 런타임 계약을 보존한다. 웹 재빌드는 Runner 갱신을 요구하지 않으며 편집형 Runner 소스만 바뀌면 해당 소스 갱신·재시작을 안내한다. 자동 업데이트 서비스·새 배포 ZIP·실제 장비 실행은 이 변경에 포함하지 않는다. 독립 리뷰와 회사 인수는 수행 증거 전 NOT_REVIEWED/NOT_RUN이다.

후속 사용자 확인: fastboot 진입 로그 `fastboot init success`는 마지막 줄이 아니며, BAT는 설치 끝에 자동 리부팅하고 `**** login : `를 출력하며 `root`로 로그인한다. 부팅/로그인 기본값은 `login :` 부분으로 하고 root 입력은 기존 RQ-60 TC 로그인 역할을 유지한다. lkshell 준비 출력과 fast 이후 출력은 구분하며 실제 lkshell 프롬프트는 미확인이다. 포팅 안내와 플러그인 적용 요청문을 함께 갱신하고, 회사 플러그인 코드/릴리스 pin의 실제 적용 여부는 확인 가능한 원본 범위와 구분한다.

추가 명시 지시로 새 EXE는 생성하지 않고 기존 Git 추적 EXE ZIP·체크섬을 삭제하며 이번 변경을 커밋·푸시한다. D-53의 기존 EXE 산출물 보존 방침은 현재 배포물에 한해 이 지시로 대체한다. 과거 Git/시험 이력·호환 소스·외부 사용자 runtime은 보존하고 현재 안내는 편집형 소스 Runner로 통일한다.

## D-67 · 2026-11-12 보드 커넥터 GUI/공통 보드·콘솔

보드 콘솔 원문과 공통 서버를 통한 plugin 오류 조회는 핵심 요구다. 검증된 RX splitter port를 코어가 소유하며 GUI는 구독만 한다. control COM 재개방/프롬프트 소비/가상포트 자동 생성은 하지 않는다. 회사 plugin 원본이 없어 참조 client/API 모의 검증과 실제 회사 수신을 구분한다. [계약](../design/BOARD_CONNECTOR_CONTRACT.md)과 [검증 기록](../testing/runs/20261112-board-connector-gui.md)을 따른다.

## D-68 · 2026-11-13 서비스 연결 토큰 제거

사용자는 보드 커넥터와 대시보드·플러그인 사이의 토큰 확인부터 제거하라고 지시했다. RQ-64로 연결용 Runner·등록·플러그인 공유 비밀을 제거한다. 기술 선택은 기존 SSH/loopback 경로 유지와 비밀이 아닌 서비스 구분 헤더다. 같은 호스트의 비브라우저 프로세스를 별도 공유 비밀로 구분하지 않으며 OS/SSH 권한을 신뢰 경계로 사용한다.

사용자 설정과 무관한 관리자 IPC 자격, 배치 lease·prepared_token·자동 브라우저 세션은 유지한다. 새 의존성·DB 이전은 없고 세 구성 요소를 함께 갱신한다. 대시보드 자동 설치 구현은 사용자가 방향 재정리를 요청한 상태로 계속 보류한다. 실제 회사 인수와 독립 검토는 수행 전 NOT_RUN / NOT_REVIEWED다.

## D-69 · 2026-11-13 커넥터 실행 단일화

사용자는 수동 설치 명령을 스크립트로 묶고 중복 스크립트를 정리하도록 지시했으며 완료 후 병합·푸시를 요청했다. RQ-65는 루트 board-connector.cmd → 표준 라이브러리 준비 코드 → 기존 GUI 경로로 구현한다. Python 자체·OpenSSH·회사 TC 패키지는 선행 조건이다. 회사 pip 설정은 재사용한다. 정상 의존성은 재설치하지 않고 변경된 의존성은 새 환경에 준비하는 것은 실행 중 환경 보존을 위한 구현 선택이다.

새 EXE/배포 ZIP·자동 대시보드 설치·실제 회사 장비 실행은 추가하지 않는다. Windows GUI/수동 Host/단순 SSH의 중복 사용자 진입점 3개는 제거하고 CLI 자동화·Linux·별도 웹 서비스·빌드는 유지한다. 실제 Windows/회사 인수는 수행 증거로 구분한다.

D-69 후속: 회사에서 Python 3.13을 사용한다는 사용자 확인에 따라 3.13 64비트를 우선 선택한다. 3.11/3.12 호환은 유지하며, 다른 Python minor의 기존 가상환경은 재사용하지 않는다. Qt 고정 버전은 변경하지 않는다. Windows 회귀 CI는 3.13으로 실행하고 기존 독립 패키징의 3.12 기준은 별도로 유지한다.

## D-70 · 2026-11-13 물리 COM 단독 소유와 GUI 정리

사용자가 real device → port multiplexer → serial proxy/PuTTY/board connector 구조와 작은 Qt GUI 개선의 구현·커밋·푸시를 승인했다. 회사 TC는 포트 번호를 받아 공통 Python 모듈에서 serial 함수를 호출한다. 기술 선택은 기존 pySerial 3.5·Qt 6.8.3 유지, Host 내 UART 소유·loopback RPC/Raw TCP, 공통 Serial 어댑터 한 곳 변경이다. 새 가상 COM 드라이버/EXE·배포 ZIP은 만들지 않는다. ADB_PROXY는 별도 경로이며 이번 UART 구현 완료와 혼동하지 않는다.

기존 RX splitter 필수 정책은 새 proxy 모드에 한해 내부 구독으로 대체한다. legacy native는 유지하며 기존 프로파일을 자동 전환하지 않는다. PuTTY 기본 조회·명시 수동 제어·TC/플래싱 배타와 사용자 입력 없는 실행 lease를 사용한다. 실제 회사 TC 공통 모듈·Windows 11/장비 인수는 별도다.

## D-71 · 2026-11-14 플러그인 중심 구현과 스크립트 정리

사용자가 전체 요구사항 독립 리뷰 후 구현을 승인했고, 원인 조치·실행 조건 확인 후 자동 재실행과 같은 원인 재발 시 중단을 확정했다. 별도 Astra/xhigh 요구사항 리뷰의 PC-R01~10을 반영한다. 새 Run은 fail-stop-analysis-v1, 과거 정책이 없는 Run과 기존 retry policy Run은 저장 당시 의미를 유지한다. 실패 latch·분석 outbox는 같은 트랜잭션에 저장한다. 회사 분석 callback은 제안만 반환하고 서버의 신뢰된 verifier가 실행 조건을 확인한다. verifier 부재·UNKNOWN·BSP acceptance 미확인은 HOLD다. 같은 복구 chain의 자동 재시도 최대3회는 무한 반복을 막는 기술 선택이며 사용자 지정 숫자는 아니다.

공통 설정은 기존 documents 저장소와 timeout 설정을 하나의 revision으로 묶고 JSON import/export에 CAS를 적용한다. Windows desired와 실제 시작된 Host 설정의 적용 receipt를 구분한다. 새 timeout은 개별 override→명시 공통값→명시 metadata→600 순서이며 기존 Run snapshot과 명시10초를 유지한다. 공통 설정에 SSH 자격을 넣지 않는다. 기존 공유 연결 토큰 제거를 유지하며 브라우저 범위·same-origin/CSRF와 실행 소유권을 확인한다.

전체 Agent Monitor 소스와 미리 빌드한 화면을 파일 해시 manifest로 전달한다. 설치 경로의 releases와 runtime을 분리하고 관리 잠금·서비스 identity로 기존 인스턴스를 재사용한다. runtime·실패 이력·기존 활성 설치를 덮어쓰지 않는다. Python/OS 의존성 자동 설치 및 실제 회사 분석기·ACON·장비 인수는 별도 접점이다. 전체 스크립트 중 동일 역할 별칭과 폐기 EXE builder를 제거하고 build-ui, serve_monitor, manage_profile처럼 역할을 표시한다. OS별 얇은 wrapper·호환 runtime·과거 시험 근거는 보존한다.

추적 RQ-67/T-240~246. [기술 기준](../design/PLUGIN_CENTRIC_INTERFACE_PLAN.md), [공개 API/운영 안내](../agents/PLUGIN_CONTROL_API.md), [구현 검증](../testing/runs/20261114-plugin-centric-implementation.md)을 따른다. 실제 운영 실행·커밋·푸시는 이번 구현 지시에 포함하지 않는다.

## D-72 · 2026-11-14 회사 접점 외 잔여 구현

사용자가 회사에서 확인할 부분을 제외한 잔여 기능 구현과 문서 갱신을 지시했다. 기본 분석은 원인·근거를 정리하고 HOLD하며 조치 완료를 추정하지 않는다. 실행 권한이 있는 운영자가 등록한 해시 고정 분석·검증 프로그램 또는 외부 플러그인 소비자가 조치와 재실행을 연계한다. BSP 연결 재실행은 기존 호스트 모듈 선택 계약을 확장해 원래 게이트와 원자적 수락을 재사용한다.

자동 정리 기본 7일·20 GiB·5분 주기·신규 자료 1시간 유예는 기술 선택이다. 실행·실패 근거를 지우지 않고 보호 자료로 인한 한도 초과와 미집계를 보고한다. GC 파일 순회·삭제가 실행 기록과 보드 제어를 장시간 막지 않도록 분리한다. 공개 도구는 지원 OS 설치 경로를 사용하고 회사 드라이버·TC 패키지는 제공된 서명/해시 자료로만 준비한다. 기존 runtime은 오프라인 검사 revision·백업 후 수락하며 불명·진행 소유권을 강제로 해제하지 않는다.
