# 요구사항 명세

사용자 확정 정책은 종합 계획의 D 번호를 따른다. 아래 RQ 번호는 구현·시험 추적용이며 번호를 재사용하지 않는다. 세부 데이터·오류 처리 방식은 구현 기준안이다. 테스트 대응은 [시험 목록](../testing/TEST_CATALOG.md)에 기록한다.

## 목적과 범위

기존 원본 OS, 벤더 수정본, 신규 원본 OS의 차이를 추적하여 벤더 의도를 보존한다. 단순 패치 적용 성공이 아니라 새 OS 반영 여부·이식 필요·제외·판단 필요를 증거로 분류하고 구현과 검증에 연결한다.

초기 범위: 웹 UI, Linux 영속 실행 관리, 두 접속 모드, 역할별 에이전트 연결, 수동 장비 시험, Jira 직접/MCP 연결 선택. 제외: 자동 플래시·자동 보드 예약·Windows 테스트 프로그램 자동 실행·수정/빌드 병렬 실행. 제품 자체 개발용 자동 시험은 초기부터 포함한다.

| ID | 요구사항과 인수 조건 | 출처 |
|---|---|---|
| RQ-01 | Windows 실행 모드는 Linux에 작업을 요청하고 Linux 실행 모드는 같은 서버의 실행 관리 기능을 사용한다. 두 모드에서 동일 job_id와 동일 상태 버전을 조회한다. UI 종료로 실행이 사라지지 않는다. | D-23 |
| RQ-02 | Linux 호스트·계정·작업 폴더·소스 기준·결과 폴더·환경 초기화·빌드 프로필을 설정한다. 경로와 권한을 실행 전 검증하고 잘못된 설정으로 Start하지 않는다. | D-10, D-17 |
| RQ-03 | Start는 명령 ID로 중복 방지한다. 실행 기준을 고정하고 전용 Claude 조정 세션을 연결한다. 세션 생성만으로 수정 작업을 시작하지 않는다. | D-01, D-11 |
| RQ-04 | 모든 모듈의 요구사항 분석 및 분석 재시도는 부트로더 완료와 무관하게 병렬 배정 가능하다. 분석은 고정 소스를 읽고 코드 수정 권한은 없다. | D-14, D-21 |
| RQ-05 | 필수 분석 후 모듈 목록·선행 그룹·변경 계획의 정확한 버전을 최초 확인한다. 확인 전 모든 모듈 설계 이후 차단. 동일 계획 재개에 단계별 승인을 반복하지 않는다. | D-01 |
| RQ-06 | 나머지 모듈의 설계 이후 실행과 재시도는 선행 그룹 전체의 유효한 필수 단계 완료 및 관련 결정 반영 후 허용한다. 순환 의존은 표시하고 임의로 게이트를 우회하지 않는다. | D-21 |
| RQ-07 | 수정과 빌드가 하나의 공유 작업 공간 잠금을 사용한다. 한 작업 수정 중 다른 작업 빌드도 금지한다. 미래 병렬화는 격리된 작업 공간·산출물·병합 정책을 전제로 한다. | D-14, D-15 |
| RQ-08 | job/module/stage/attempt/session 식별자를 분리한다. 모듈은 재시도·세션 종료 뒤에도 유지하며 목록 변경은 계획 버전과 이력으로 관리한다. | D-27 |
| RQ-09 | 모듈별 분석·설계·코드·빌드·검증·장비 테스트 6단계를 관리한다. 각 완료는 결과물·입력 기준·필수 시험/리뷰 근거가 있어야 한다. | §5.4 |
| RQ-10 | 실패 단계 재시도는 새로운 attempt를 생성하고 이전 실패를 보존한다. 중복 클릭·실행 불명 상태에서 두 작업을 만들지 않는다. 수동 시험 재시도는 새 수동 결과 대기다. | D-20 |
| RQ-11 | Linux 영속 상태가 기준이다. 명령과 조회를 분리하고 중단·재접속·역순 이벤트에서 과거 결과로 최신 상태를 덮어쓰지 않는다. | §2.10 |
| RQ-12 | OpenCode 기본 BSP 구현, 동일 원인 수정 2회 실패 또는 근거 있는 난항 시 Claude Opus 전환. 실제 수정 시도만 계산하고 인계 자료와 이전 실행 종료를 확인한다. | D-30, D-31 |
| RQ-13 | OpenCode 작성은 Claude, Claude 작성은 Codex 리뷰한다. 작성 후 소스가 달라지면 재리뷰한다. 미설치 도구는 Claude 대체하되 구현과 별도 리뷰 실행을 기록한다. | D-30, D-33 |

| RQ-16 | 새 판단은 내부 검토 항목으로 먼저 저장하고 Jira 연결한다. 그 판단에 의존하는 작업만 대기한다. 일반 실패와 수정 요청은 자동으로 새 판단으로 간주하지 않는다. | D-03 |
| RQ-17 | 사내 Jira 직접 설정 또는 실제 Linux Claude 환경의 MCP 목록에서 선택한다. 등록과 실제 기능 확인을 구분하고 미지원·연결 실패·인증 실패를 표시한다. | D-35 |

## 공통 인수 조건

- 모의 결과와 실제 결과에 명시적 구분이 있다. 설치되어 있다는 사용자 진술과 실제 실행 확인을 분리한다.
- 작업 불명·연결 끊김을 실패나 완료로 추측하지 않는다. 마지막 동기화 시각과 현재 확인 상태를 보여준다.
- 운영 환경별 필수 값이 없으면 설정 항목을 안내하고 해당 실행만 차단한다. 실제 호스트·도구 모델 ID·Jira 필드를 임의로 채우지 않는다.
- 예외/N/A는 사유·결정자·적용 범위·버전을 기록한다. 모델 자체 판단으로 필수 시험을 제외하지 않는다.
