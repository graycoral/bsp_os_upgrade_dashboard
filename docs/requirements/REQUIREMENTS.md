# 요구사항 명세

사용자 확정 정책은 종합 계획의 D 번호를 따른다. 아래 RQ 번호는 구현·시험 추적용이며 번호를 재사용하지 않는다. 세부 데이터·오류 처리 방식은 구현 기준안이다. 테스트 대응은 [시험 목록](../testing/TEST_CATALOG.md)에 기록한다.

## 2026-11-06 TC 소스 위치와 확인된 Git 브랜치 · RQ-56

| ID | 요구사항 | 근거 |
|---|---|---|
| RQ-56 | GUI Test의 TC 원본을 서버 호스트의 절대 폴더 경로 또는 GitHub/Gerrit 등의 Git clone URL로 지정하고 소스 확인 후 실제 발견된 브랜치/커밋을 선택하여 적용한다. 적용한 관리 스냅샷을 목록·Suite·Preflight·실행에 연결하고 Runner 미연결 또는 구버전의 실행 불가 이유를 표시한다. 전체 설정과 Test 현황은 같은 소스 편집기와 draft를 공유한다. | 사용자 후속 지시; D-60; T-176~182 |

입력·확인·브랜치 선택·적용을 구분하며 입력을 바꾸면 이전 확인 결과와 늦게 도착한 응답을 폐기한다. 현재 적용된 위치/브랜치/커밋/소스 기준/설정 버전은 편집 중 값과 별도로 표시한다. Git이 아닌 폴더에는 가상 브랜치를 만들지 않고 현재 파일을 스냅샷으로 고정한다. Git 원본은 선택한 커밋의 파일을 사용하며 미커밋 변경을 포함하거나 사용자의 작업 트리를 checkout하지 않는다. Git 인증은 서버 환경을 사용하고 URL에 암호·토큰을 저장하지 않는다.

Runner가 끊겨도 서버에서 소스를 준비하고 카탈로그를 볼 수 있다. 소스 전달 준비와 보드 연결·Preflight·실제 시험 통과를 구분하며 지원하지 않는 Runner에는 업데이트 필요를 표시한다. 소스 적용 성공은 TC 선택·순서·개별 반복·전체 반복·Suite 기준·Preflight를 초기화하고 반환된 정확한 카탈로그로 교체한다. 미저장 명령과 과거 Run의 소스/결과는 유지한다. 적용 실패는 현재 소스와 목록을 바꾸지 않는다. 기존 모드는 유지하고 관리 소스에서 기존 기본/Runner 공유 소스로 돌아가는 확인·적용 경로도 제공한다. default/live 작업 공간의 소스는 분리하며 소스 적용은 Mock/실제 실행 모드를 변경하지 않는다.

계약·실행 경로는 [GUI Test 계약](../design/GUI_TEST_CONTRACT.md), 화면은 [화면 명세](../design/UI_SPEC.md), 구현·독립 리뷰·모의/실제 시험 구분은 [설정 동기화 기록](../testing/runs/20261106-settings-sync.md)에 남긴다. 개발 중 실제 원격 Git/모델·보드·Jira 호출은 별도 실행 증거 없이 완료로 처리하지 않는다.

## 2026-11-06 전체 환경 설정과 탭별 동기화 · RQ-55

| ID | 요구사항 | 근거 |
|---|---|---|
| RQ-55 | 환경 설정에서 기존 BSP 및 GUI Test 설정 전체를 편집하고 각 그룹과 전체를 접고 펼친다. 대시보드의 실행 환경·에이전트/빌드·구조화 보고/조정·모듈 설정, 사람 검토/Jira의 Jira 설정, Test 현황의 GUI 설정은 전체 설정과 동일한 미저장 입력을 양방향으로 공유한다. 탭 이동과 접기는 입력·검증 오류·선택 순서·반복 횟수를 보존한다. | 사용자 구현 지시; D-59; T-169~175 |

GUI Test의 소스/Git 정보·보드/COM·명령·실행·Suite 및 브라우저 보기 모드를 전체 설정에 포함한다. TC 목록의 검색·선택·순서·개별 반복 편집과 Run 선택·실행·결과는 Test 현황에서만 제공한다. 같은 컴포넌트의 설정 입력은 양쪽에서 공유한다. 보기 모드는 통합 Test 현황 내부 설정에서도 편집하며 명시적 적용/재로드를 유지한다. 기존 환경 설정 전용 배치 요구는 이번 지시로 대체한다. 다이어그램·실행 기록에 독립 설정을 새로 만들지 않는다.

BSP 프로필 저장은 새 작업부터 적용하며 기존 job snapshot과 API 설정 버전을 유지한다. GUI 연결 프로파일·명령·Suite 저장 및 브라우저 모드 적용은 각자의 저장 범위를 명시한다. 접기 버튼은 키보드와 `aria-expanded`/`aria-controls`를 제공하며 숨긴 입력은 포커스 대상에서 제외한다. 저장 오류는 해당 그룹과 native details를 먼저 열고 오류 입력으로 포커스를 옮긴다. 접기 상태는 브라우저에 저장하되 저장소 접근 실패 시에도 조작할 수 있다.

현재 변경은 UI와 문서 범위이며 API·DB 이전이나 실제 외부 실행을 추가하지 않는다. [화면 명세](../design/UI_SPEC.md), [검증 기록](../testing/runs/20261106-settings-sync.md)에 구현·독립 리뷰·시험 증거와 미수행 범위를 구분해 남긴다.

## 2026-11-05 TC 소스 Git 정보 · RQ-52

| ID | 요구사항 | 근거 |
|---|---|---|
| RQ-52 | 설정된 원본 TC 폴더의 읽기 전용 Git 정보를 표시하고 자격 증명을 제거하며 파일 snapshot 기준과 구분한다. 미제공·비 Git·조회 실패는 명시하고 실행 기준을 바꾸지 않는다. | 사용자 요청; D-55; T-162 |

사용자 요청으로 TC 소스 설정에 저장소 경로·원격 주소·현재 브랜치·커밋을 표시한다. 설정된 원본 TC 경로를 읽기 전용으로 조사하고 원격 주소의 자격 증명은 제거한다. 기존 `catalog.revision`은 파일 스냅샷 해시이므로 Git HEAD와 구분한다. 비 Git·미설치·미연결·이전 Runner의 정보 미제공을 명시하며 개발 저장소의 정보를 TC 정보로 대체하지 않는다. checkout·pull·네트워크 호출이나 실행 기준 변경은 없다. D-55/T-162.

## 2026-11-05 모듈별 TC 자동 목록 · RQ-53

| ID | 요구사항 | 근거 |
|---|---|---|
| RQ-53 | 서버의 현재 모듈 device_test 문맥에서 관련 TC만 자동 준비한다. 오래된 문맥·잘못된 의존을 차단하고 사용자 선택·고정 Run·자동 파이프라인 소유권과 명시적 시작을 보존한다. | 사용자 요청; D-56; T-163 |

Ethernet 등 현재 작업의 모듈이 서버의 `device_test` Attempt에 들어가면 관련 TC를 자동 검색해 Test 현황 목록·선택에 포함한다. 명시적 모듈 연결을 우선하고 정규화한 폴더/파일명 토큰을 보조 기준으로 사용한다. `Ethernet`과 `ethernet`은 같게 처리하되 `notethernet`·`network`·`net`을 임의 동의어로 취급하지 않는다. 대상 외 모듈 TC를 자동 선택하지 않으며 0건·선택 불가·선행 TC 누락/순환을 표시하고 시작을 차단한다.

Job·모듈·Attempt·계획·fingerprint·카탈로그 기준으로 오래된 응답을 거부하고 같은 문맥의 반복 조회로 사용자 선택을 계속 덮어쓰지 않는다. 목록 변경은 Preflight를 무효화하며 기존 Run을 변경하지 않는다. 이미 D-48 자동 파이프라인에 배정한 TC는 고정 목록을 표시하고 별도 GUI Run으로 중복 배정하지 않는다. 자동 검색은 목록 준비이며 수동 기본값·명시적 시작·D-48의 승인된 사례 매핑·최종 사람 검토는 유지한다. D-56/T-163.

## 2026-11-04 메인 종합 화면 후속 · RQ-19/20

D-52 사용자 승인에 따라 RQ-19의 분석/구현/검증/빌드/테스트 표시를 다섯 대형 카드에서 하나의 컴팩트 진행 띠로 바꾼다. 기존 서버 집계값·단계 이름·완료/필수 수와 해당 없음/0% 구분을 보존한다. 데스크톱에서는 다섯 구획을 한 줄·160px 이내 높이에 표시하고 작은 화면에서는 컴팩트 행으로 전환한다. 진행률에는 같은 파란 강조색을 쓰며 의미가 있는 상태 배지 색을 유지한다.

RQ-20 후속: 주요 설명·집계·현재 단계/상태/대기 이유를 12~13px와 텍스트 대비 4.5:1 이상으로 표시한다. 320/375/414/768/1280px에서 페이지 가로 넘침 없이 긴 작업명·소스·경로를 읽을 수 있고, 모듈 표 내부의 가로 스크롤·검색·그룹 필터·키보드 펼침을 유지한다. 기능 없는 영문 구획 문구와 U 아바타·상단 고정 장비 테스트 문구는 공통 셸에서 제거한다. 메인 전용 스타일은 다이어그램/GUI Test로 전파하지 않는다.

이 변경은 P3 표시 개선이며 RQ-11의 조회 수용 규칙과 RQ-24의 통합 검증·최종 사람 검토 조건을 유지한다. API/DB/진행률 계산·실행 게이트·기존 버튼 핸들러·외부 연동은 변경하지 않는다. T-59/T-150 및 영향받는 기존 화면 회귀를 실제 실행 근거와 함께 확인한다.

## 목적과 범위

기존 원본 OS, 벤더 수정본, 신규 원본 OS의 차이를 추적하여 벤더 의도를 보존한다. 단순 패치 적용 성공이 아니라 새 OS 반영 여부·이식 필요·제외·판단 필요를 증거로 분류하고 구현과 검증에 연결한다.

초기 범위: 웹 UI, Linux 영속 실행 관리, 두 접속 모드, 역할별 에이전트 연결, 수동 장비 시험, Jira 직접/MCP 연결 선택. 제외: 자동 플래시·자동 보드 예약·Windows 테스트 프로그램 자동 실행·수정/빌드 병렬 실행. 제품 자체 개발용 자동 시험은 초기부터 포함한다.

## 공통 인수 조건

- 모의 결과와 실제 결과에 명시적 구분이 있다. 설치되어 있다는 사용자 진술과 실제 실행 확인을 분리한다.
- 작업 불명·연결 끊김을 실패나 완료로 추측하지 않는다. 마지막 동기화 시각과 현재 확인 상태를 보여준다.
- 운영 환경별 필수 값이 없으면 설정 항목을 안내하고 해당 실행만 차단한다. 실제 호스트·도구 모델 ID·Jira 필드를 임의로 채우지 않는다.
- 예외/N/A는 사유·결정자·적용 범위·버전을 기록한다. 모델 자체 판단으로 필수 시험을 제외하지 않는다.

RQ-30~34는 2026-10-12 D-39에서 문서 목표로 정의했다. 당시 구현하지 않았고 T-71~85를 NOT_RUN으로 추가한 이력은 보존한다. 2026-11-06 D-58로 O1~O4/v2 구현·로컬 검증을 진행하며 기본 v1·조정 OFF를 유지한다. [현재 실행 기록](../testing/runs/20261106-orchestration-v2.md)의 부분 결과를 전체 인수 PASS로 해석하지 않는다. O5/T-85 실제 외부 인수는 별도다. 필드/권한의 단일 기준은 [오케스트레이터 명세](../design/ORCHESTRATOR_SPEC.md), [모듈 보고 계약](../design/AGENT_STATUS_CONTRACT.md)이다.

### 구현 선택과 인수 경계

- TC별/전체 횟수는 각 1~100, 합계 최대 10,000회다. 전체 회차마다 선택 순서대로 각 TC를 지정 횟수 연속 실행한다. 오류 복구는 같은 계획 항목을 재시도한다.
- 화면 정렬은 실제 실행 순서를 바꾸지 않는다. 2026-11-03 사용자 후속 요청에 따라 실행 순서 변경은 TC 드래그만 제공하고 위아래 이동 버튼은 제거한다. 폴더를 넘는 전체 순서는 별도 펼침 목록에서 확인한다.
