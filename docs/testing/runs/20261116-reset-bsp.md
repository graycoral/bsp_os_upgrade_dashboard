# 미완료 BSP 기록의 일괄 초기화

RQ-68 / T-254 / REG-0100. 기준 `ef9edbe99baedaa069273c811270d3ff6ce33555`.

## 재현과 원인

사용자는 REG-0099 수정 후에도 `RESET_BLOCKED`와 진행·대기·일시정지·종료 불명 작업이 남았다는 오류를 보고했다. 회사 DB 원문은 수집하지 않았다. 직전 게시 버전에 정상 Engine.create로 생성한 PENDING BSP 작업과 PAUSED 하드웨어 TC 기록을 함께 두면 같은 오류가 재현된다.

일반 stop은 BSP 작업에 최종 검토와 모든 단계 성공을 요구한다. 따라서 실제 실행이 없는 실패·대기·일시정지 작업도 종료를 막았다. REG-0099는 TC와 예약을 취소했지만 이런 BSP 기록을 함께 처리하지 않았다.

## 변경

reset의 기존 세션 취소 후 모든 runtime DB에서 BEGIN IMMEDIATE를 획득한다. 이 잠금 안에서 현재 실행·예약·lease·프로세스 receipt와 Jira/질문/시도 종료 근거를 재확인한다. 새 실행 claim은 쓰기 transaction에서 대기한다. 실행이 없는 BSP와 이전 GUI Test 저장소의 기록은 별도 SQLite 백업을 만들고 초기화 receipt에 먼저 기록한 뒤 관련 테이블을 비운다. 최종 리뷰와 실행 성공의 원래 값은 백업에 보존한다.

새 백업은 원래 runtime 백업 아래 pre-stop-*에 있으며 pre_stop_archives로 누적한다. DB별 commit 도중 실패하면 이미 기록한 백업을 유지하고 RESET_DRAINING에서 재시도한다. 최초 backup과 각 BSP archive의 해시를 검증한다. BSP 정리 후 일반 stop과 Worker 잠금 아래 남은 GUI/연결 오류 기록 초기화를 이어간다. 환경·연결 설정은 유지한다. DB schema 변경은 없다.

일반 종료와 reset은 공통 process_receipt_stopped로 기존 외부 프로세스 종료·미실행·모의 근거를 확인한다. 실행 중 Jira 전송, 질문, 종료 불명 시도와 held lease는 초기화를 보류한다.

## 검증

원본 로그와 파일별 manifest는 `.local-reports/20261116-reset-bsp/`에 로컬 전용으로 보관한다. main 기준 격리 checkout에 이번 코드·시험 4개만 적용했다. 별도 GUI Test WIP 7개는 포함하지 않았다. 실제 회사/보드 작업은 수행하지 않았다.

영향 회귀 명령은 아래와 같다.

```bash
python -m pytest tests/test_agent_monitor_reset_live.py tests/test_agent_monitor_manager.py tests/test_agent_monitor_recovery.py tests/test_agent_monitor_lifecycle.py tests/test_agent_monitor_delivery.py tests/test_setup_runtime.py tests/test_engine.py backend/gui_test/tests/test_core.py backend/gui_test/tests/test_plugin_integration_recovery.py backend/gui_test/tests/test_session_deletion.py -q -rs
```

확장 회귀에는 tests/test_orchestration_worker.py도 포함했다. 실패 8건은 Linux /proc boot_id와 Linux 프로세스 identity/receipt 검증을 macOS에서 수행한 결과다. 수정 전 별도 checkout에서도 같은 8건이 실패했다. 해당 파일과 제품 Worker/receipt 코드는 이번 변경 대상에 포함되지 않았다. Linux 실제 프로세스 검증은 NOT_RUN으로 남긴다.

최종 HTTP 완료 경로는 TC 4종 × 기본/공유 DB 2종 × 추가 기록 5종의 40개 조합이다. 추가 기록은 없음, BSP PENDING/FAILED/PAUSED, 현재 API에 표시되지 않는 이전 GUI Test의 PAUSED 예약이다. 실제 API·기존 supervisor 종료 루프·실제 DB를 연결하고 Worker/Windows 응답은 시험용 객체를 사용했다. 정상 생성 BSP 기록의 원래 상태와 final_review=None이 백업에 보존되고 현재 DB가 비워진 것을 확인했다.

추가 시험은 writer 잠금 중 Engine.claim 경합, archive receipt 저장 실패, 다중 DB 두 번째 commit 실패 후 재시도, Jira/질문/attempt/lease/외부 프로세스 종료 근거 누락 거부다. 이 시험은 실제 장비나 모델 호출 없이 수행했다.

영향 회귀 SKIP 8개는 UI 빌드 자산 복사 인수 1개와 Windows DPAPI/PowerShell/CMD 7개다. 확장 worker의 Windows 자식 프로세스 검증 1개가 추가 SKIP이며 Starlette TestClient httpx deprecation warning 1건이 있었다.

코드 manifest SHA-256 `645052dff5439899e90986206f2a4b86d19c3b04684f86b1891787c7fa340a8a`. 시험 manifest SHA-256 `c00b780e5aeddaf25809e424b7320a8c265678ba7d637d1f5ab74f79e165349c`.
