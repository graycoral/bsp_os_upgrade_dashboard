# 이식 가능한 기능

승인된 작업 범위에서 기존 경계를 조사하고 재사용 가능한 기능과 호스트 연결을 함께 다룬다. 이 스킬은 저장소 전체 재구성이나 외부 실행을 승인하지 않는다. 사용자 지시와 적용되는 저장소·회사 정책 및 역할 배정을 우선한다.

## 읽기와 범위

- 필수 로컬/회사 정책을 먼저 확인한다. 회사 적용은 해당 PORT, `COMPANY_MAP.md`, `APPLIED.md`, 관련 코드·시험부터 읽고 불명확한 의존성·계약·정책만 확장한다. 이 저장소에서 개발할 때는 [AGENTS.md](../../../AGENTS.md)의 일반 필수 읽기 순서도 따른다.
- 문서·로그 전체를 일괄 수집하지 않는다. 요구사항은 인수 조건이며 이미 검증된 코드를 재구현하라는 지시가 아니다.
- 현재 구현 경로와 접점을 먼저 확인한다. 이동이 승인된 경우 import, 타입 검사, 빌드, 시험, 패키징 소비자와 현재 문서를 갱신하고 과거 고정 버전 기록은 보존한다.

## 기능 경계

- 응집된 기능 모듈과 명시적 호스트 인터페이스/어댑터를 우선한다. 불필요한 조각화, 새 서비스 또는 npm 게시를 전제로 하지 않는다.
- 이 저장소의 재사용 프런트엔드는 `packages/<feature>` 관례를 따르고 회사에서는 기존 구조를 따른다. 데이터·인증·API·폴링·탭·DB 연결은 호스트에 둔다. Python은 기존 backend/패키지 관례를 따른다. 공유 코어에서 호스트 내부를 import하지 않는다.
- 공개 입력·출력과 의존성을 명확히 하고 독립 사용을 뒷받침하는 계약과 시험을 제공한다. 주입 인터페이스나 기존 등록 실행 어댑터를 활용하며 임의의 회사 스택과 호환된다고 단정하지 않는다.
- 공통 기능 전달 단위는 재사용 코드, 호스트 연결, 계약/시험, 짧은 PORT 안내다.

## 원본 준비

[이식 절차와 양식](../../../docs/porting/README.md)을 사용한다. 원본 기준/대상 커밋, 선행 조건과 의존성, 파일·심볼 목록, 변경 없는 코어와 회사별 어댑터, 필요한 데이터 이전·복원, 실행 명령·증거·미검증 범위를 기록한다. 실제 실행한 검증만 보고한다.

## 회사 적용

- 회사 기준과 부분 적용 상태를 먼저 확인하고 기존 기능과 개선을 보존한다. 파일 덮어쓰기나 cherry-pick의 안전성을 가정하지 않고 원본 전후와 회사 접점을 비교한다.
- 공통 결함은 원본 공통 코드에서 해결할 수 있는지 살피고 회사 고유 차이는 어댑터에서 조정한다. 관련 매핑만 갱신하고 보존 조건, 원본/회사 커밋, 부분 적용과 시험을 회사 기록에 남긴다.
- 지정 시험과 영향받는 호스트 회귀 시험을 실행하고 과거 FAIL을 보존하며 미실행 시험은 NOT_RUN으로 구분한다.
- 이식 지시에 포함된 회사 검증을 수행하되 실제 장비 적용·모델 호출·외부 운영 실행은 사용자가 승인한 범위를 따른다. 기존 승인이 있는 작업은 다시 승인받지 않는다. 로컬 또는 모의 결과를 실제 인수로 표시하지 않는다.
